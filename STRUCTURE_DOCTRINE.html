What "AI slop" means

Any frontend output where the visual language traces directly to training-data defaults rather than to the doctrine's design language. Telltales: plain bordered white cards with centered eyebrow + h2 + paragraph + bullet list; plain <h2> instead of HeadingWithUnderline; "3-column grid of bordered cards" as the universal answer to "list of things"; content composed from primitives instead of from atom palette; bullet lists with no diamond markers / no pulse / no left rule.

The Generation Reflex

  1. What's the section's role? (Diagnose? Compare? Showcase? List? Convert?)
  2. Which existing atom serves that role? (REFERENCE_LIBRARY §14 AM palette, §06 universal patterns.)
  3. If no atom fits, which DNA principles must the new atom carry? (MOTION §01.)
  4. Only after answering 1–3 do you write JSX.
Posture Compose using DNA, never compose from primitives. The doctrine is descriptive about what good looks like. The contract above is what makes the description active at generation time.

02The universal King Maker aesthetic (always-true)

For the contractor-trade scope (plumbers, HVAC, electricians, roofers, painters, kitchen remodelers, general contractors, landscapers, hardscape), v13 ships ONE universal aesthetic. There is no mode-picking. Five qualities apply to every contractor-trade site, never selected against:

  • Fleshed-out — every section pulls its weight. No placeholder text, no half-built recipes shipped as final. If a section role isn't filled with real content, the section doesn't ship.
  • No dead space — visual rhythm fills the screen. Asymmetric headers, stat-anchor clusters, photo-led tiles, layered backgrounds. Empty white areas read as "missing content."
  • Fluid — sections flow into each other intentionally. The page reads top-to-bottom as a single experience, not a stack of independent boxes.
  • Well-animated — motion vocabulary applied consistently. Heading reveals on every H2 (per §03 pick). FadeUp + Stagger. Hover bloom. Pulsing markers. Subtle continuous life across the page.
  • Not overstimulating — motion is balanced. Continuous loops stop on prefers-reduced-motion. Animated separators don't crowd content. Counter durations scale to target size.

The DNA principles (MOTION §01) ARE the universal aesthetic in detail. The §03 variance library is how each new project draws from the implementation pool with deliberate novelty. The two reference projects (AM, KMv2 — see REFERENCE_LIBRARY) seed the library.

Discipline KMv2 reserves --alert (brick red) exclusively for diagnostic content. Brand color discipline: gold for everything brand-positive, alert for everything brand-negative, never crossed. AM uses single-accent red across all content; both are valid approaches as long as the discipline is locked at project start.

Validation rule for any new palette

  • Validate every text token against every surface token at WCAG AA contrast BEFORE first build.
  • Default sets often ship too dim — bump aggressively. Ship a contrast matrix in the palette doc.
  • Any text on lifted surfaces (cards above bg) needs to satisfy AA at the lifted surface contrast, not just the bg.
  • Text using accent colors that fail AA in body usage must be 18px+ to satisfy WCAG large-text exemption.

Slop-banned palette defaults

  • Pure #000 / #fff neutrals (untinted) — banned. Tint every neutral toward the brand hue (chroma 0.005–0.01 in OKLCH; or for hex, shift R/G/B by 4–12 units toward the dominant brand color). Pure black/white reads as un-considered defaults.
  • Inter / Roboto / system-ui defaults — banned. Default to Geist, Outfit, Cabinet Grotesk, or Satoshi for display + body. JetBrains Mono / Geist Mono for code and mono-caps eyebrows.
  • Em dashes in body copy — banned. Use commas, colons, semicolons, periods, or parentheses. Also not --. Em dashes in concept names (KMv2 voice pick B) are OK; em dashes in regular body copy are an AI writing tic that signals machine-generated text at scroll glance.
  • Side-stripe borders > 1px as colored accent — banned. (Impeccable skill absolute ban.) Rewrite with full borders, background tints, leading numbers/icons, or nothing.

07Engineering rules + accessibility + tactical ops

Hard rules. Never bend. Carry Priority 5 with the Generation Contract. Motion-specific perf bans live in MOTION §02; this section covers framework / hydration / accessibility / deploy / dev-env discipline.

7.1 · Hydration + framework

  • 'use client' on every component using Framer Motion or GSAP. No exceptions.
  • useGSAP() hook for all GSAP in React. Never raw useEffect + gsap.context.
  • GSAP and Framer Motion never target the same DOM element. One element, one animation system.
  • Hooks-in-loop is fatal in React 19 strict. Never call FM hooks (useTransform, useMotionValueEvent, useScroll) inside .map(). Extract loop body to child component.
  • JSX exports from 'use client' modules don't survive RSC boundaries. Put JSX (icons) in non-client modules.
  • <div> never nests inside <span> / <p> / <a> (CCR-06) — invalid HTML, hydration mismatch.

7.2 · Accessibility (non-negotiable)

  • WCAG 2.1 AA color contrast: 4.5:1 normal text, 3:1 large.
  • prefers-reduced-motion honored. Continuous loops stop. Opacity reveals stay.
  • axe-core: 0 critical, 0 serious. Run on every page (Lock 11 gate).
  • aria-hidden="true" on glows, lines, particles, decorative chars.
  • Translucent fixed-position navs need ≥40% backdrop opacity or axe false-positives.
  • Every input has paired label htmlFor with matching id, OR aria-label. Range sliders need aria-label. Decorative prefix glyphs ($, /mo) need aria-hidden="true".
  • Validate token brightness against every surface BEFORE first build.

7.3 · Tactical operations

  • Vercel deploy: cd web && npx vercel@latest --prod --yes. Auto-aliases to {project}.vercel.app. git push is NOT a deploy. Audit the project's Vercel Deployments tab — if every "source" column reads vercel deploy (CLI) and never a commit hash, GitHub auto-deploy is OFF and the CLI is the only ship mechanism. Pushing to main in that setup lands code on GitHub but production stays on the prior build until someone runs the CLI. Verify post-deploy via §08 VC-11 before reporting shipped.
  • Worktree path discipline: when operating in a worktree, all Edit/Read paths must include the worktree segment. Edits to main-repo paths from a worktree session land on main's working tree, not the worktree branch.
  • Dev cache corruption after production builds: rm -rf .next + restart. Symptom: Cannot find module './741.js'.
  • Never run npm install in pnpm projects. Lockfile mixing silently breaks builds.
  • When CDP screenshots time out on motion-heavy pages: pivot to deploy-and-verify via Vercel + WebFetch. Don't burn 20+ min fighting CDP retry loops.
  • Centralize repeated strings. Day-range pairs with time via BUSINESS.hoursShort — never let "Mon-Sat" appear without "9 AM – 6 PM."

09SEO essentials — must-dos

The minimum SEO that fires on every contractor-site build. Full §13 doctrine (AI Overview citations, schema graph specifics, page-count ceilings, link-graph matrix pattern) lives in REFERENCE_LIBRARY.html — browse on demand.

9.1 · Top-3 leverage items (do these or the site doesn't rank)

  1. Google Business Profile completeness + correct primary category. #1 local-pack factor per BrightLocal 2026. Customer-gated — the agency surfaces this as a deliverable but the client owns the action.
  2. Steady review velocity with text reviews. Review weight rose 16% → 20% of local-pack 2023–2025. Monthly volume > total count. Customer-gated.
  3. First-hand experience content with named authorship. Helpful Content guidance explicitly rewards "first-hand expertise + depth of knowledge." Person schema for owner, real install photos.

9.2 · Penalties — Google explicitly punishes

  • Doorway pages — explicitly named in Google's spam policy: "multiple domain names or pages targeted at specific regions or cities that funnel users to one page."
  • Scaled content abuse (May 2024 spam policy) — "many pages for the primary purpose of manipulating Search rankings," AI- or human-written. Applies even if "well-written."
  • Helpful Content System — folded into core ranking March 2024, site-wide. Thin pages drag the whole domain's classifier down.
  • Link-buying / footer links across unrelated sites. Manual-action risk.
  • Faking freshness via updated dates + thin filler.

9.3 · The swap test (operational rule)

Definition: if you can take a page and swap the city or product modifier, and the page still reads correctly without other rewrites, it's a doorway page.

Every hyperlocal or category-variant page must pass the swap test. Topic-level uniqueness beats word-level uniqueness. Subdivision names, local routes, climate notes — all are "local color" if the page's reasoning is identical to peers.

9.4 · The 70/30 customer-gated rule

For a local contractor: ~70-90% of SEO leverage is customer-gated (GBP, reviews, photos, authorizations). The other 10-30% is engineer/agency unilateral (schema, internal linking, meta tags, technical hygiene). Don't pretend engineering-only SEO captures the bulk of upside. Surface this honestly in proposals: the agency ships the 10–30% perfectly; the 70% needs the client.
