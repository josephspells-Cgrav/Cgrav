07Anti-pattern catalog — rendered

Failure modes shown rendered, not described. Each one was hit during the AM build and cost real time before the fix landed. Avoid in future builds.

7.1 · Red-on-navy caps eyebrow

text-red against bg-navy is dark-on-dark. Renders ~2.5:1 — illegible. Hit on FooterCTA, FAQ STILL NOT SURE, SpecDeck eyebrow, Footer column headers — fixed sitewide in v9.

❌ Anti-pattern · red caps on navy
Step 1 · Fast Estimate
✅ Fix · white caps + red dot accent

7.2 · FadeUp / Stagger / SlideIn negative viewport margin

The doctrine pre-v9 used margin: "-260px" for IntersectionObserver triggers and called it "pre-trigger." This is BACKWARDS — negative root margin SHRINKS the trigger box, meaning elements have to scroll DEEPER into the viewport before firing. The CTAs on home teasers were appearing way too late as a result.

❌ Pre-v9 · negative margin POST-triggers
margin = "-260px"  // Element triggers
                   // 260px AFTER it enters
                   // viewport. Late.
✅ v9 · positive margin actually pre-triggers
margin = "200px"   // Trigger zone expands
                   // 200px ABOVE viewport.
                   // Fires early.
Audit needed Any earlier project still using -260px defaults from v3-v8 inherited the same bug. Audit on next handoff: search for margin = "-260px" in motion components, flip to positive 200px.

7.3 · JSX exported from a 'use client' module crossing the RSC boundary

Storing JSX (e.g., SVG icon constants) in a 'use client' module and importing them from a server component to pass as props strips them at the boundary. They render as nothing.

❌ Pre-v9 · JSX in 'use client' module
// SignsGrid.tsx
'use client';
export const SignIcons = {
  draft: (<svg>...</svg>),
};

// app/windows/page.tsx (server)
import { SignIcons } from '@/.../SignsGrid';
// SignIcons.draft → client ref → empty render
✅ v9 · JSX in plain (non-client) module
// SignIcons.tsx (no 'use client')
export const SignIcons = {
  draft: (<svg>...</svg>),
};

// app/windows/page.tsx (server)
import { SignIcons } from '@/.../SignIcons';
// JSX survives RSC boundary, renders properly

7.4 · Bar fill = "score" instead of literal magnitude

If the BAR represents "this material is GOOD at maintenance", LOW maintenance gets a HIGH bar (because low is good). Confusing — viewers expect "the bar shows the value of the word." Fix: bars represent literal magnitude. LOW = short bar, HIGH = long bar. Wood (HIGH maintenance) = nearly-full bar.

❌ Score-as-fill (confusing)
MAINTENANCELOW
MAINTENANCEHIGH

"LOW maintenance" with a near-full bar reads as a contradiction.

✅ Magnitude-as-fill (intuitive)
MAINTENANCELOW
MAINTENANCEHIGH

Bar literally matches the word. Reads correctly without thought.

7.5 · StatCounter with fixed duration on small targets

1.1s duration to count 0→6 means the user sees "0" for too long. v9 scales duration by target size: ≤10 → 0.45s, ≤50 → 0.6s, ≤100 → 0.8s, larger → 1.0s. Small numbers land cleanly without holding visibly at 0.

7.6 · Other cataloged anti-patterns (v8 carry-forward)

  • Wide outer glow halos — bleed creates a strikethrough effect through the heading. Cap at 2px alpha 0.55.
  • mb-* inside HeadingWithUnderline className — the component routes margin classes to the outer wrapper; inner mb creates an overline effect.
  • filter: blur(*) on text animations — removed sitewide. Opacity + offset only.
  • "Playing card" 4-up color-coded stat blocks — explicitly rejected. Use structured cards with rhythm.
  • Gold/yellow/teal in AM, red in KMv2 — palette discipline. Substitute brand color when adapting references.
  • Deploying without clearing dev cache — webpack .next corruption is recurring. rm -rf .next + restart between heavy edit batches.
  • playbackRate < 1.0 on hero video — halves frame rate, visible stutter. Generate at native long duration instead.
  • Hooks-in-loop in React 19 strict — kills the parent silently. Extract loop body to child component (see v8 §1.2).

08Engineering rules

Hard rules. Never bend. Carries forward from v8 §1 with v9 additions noted.

8.1 · Performance bans

IDBanReason
PP-08No infinite boxShadow animationsReal paint cost. Use opacity or filter.
PP-09No width/height/top/left animationsLayout reflow per frame. Use transform + opacity only.
PP-10No setInterval counterssetInterval drifts and re-renders. Use useMotionValue or rAF.
PP-11No HTML video playbackRate < 1.0Halves frame rate → stutter. Generate at native long duration.
CCR-06No <div> inside <span>/<p>/<a>Invalid HTML. Hydration mismatches.
PP-12 ⭐No negative IntersectionObserver root margin defaults claiming "pre-trigger"Negative margin POST-triggers. Use positive (e.g. 200px) for true pre-trigger. v9 fix.

8.2 · Hydration & framework

  • 'use client' on every component using Framer Motion or GSAP. No exceptions.
  • useGSAP() hook for all GSAP in React. Never raw useEffect + gsap.context.
  • GSAP and Framer Motion never target the same DOM element. One element, one animation system.
  • Hooks-in-loop is fatal in React 19 strict. Never call FM hooks (useTransform, useMotionValueEvent, useScroll) inside .map(). Extract loop body to child component.
  • JSX exports from 'use client' modules don't survive RSC boundaries. Put JSX (icons, etc.) in non-client modules. v9 lesson — see Anti §7.3.

8.3 · Accessibility (non-negotiable)

  • WCAG 2.1 AA color contrast: 4.5:1 normal text, 3:1 large.
  • prefers-reduced-motion honored. Continuous loops stop. Opacity reveals stay.
  • axe-core: 0 critical, 0 serious. Run on every page.
  • aria-hidden="true" on glows, lines, particles, decorative chars.
  • Translucent fixed-position navs need ≥40% backdrop opacity at all scroll positions or axe false-positives.
  • Every input has paired label htmlFor with matching id, OR aria-label. Range sliders need aria-label.
  • Validate token brightness against every surface BEFORE first build (palette tables in §04).

8.4 · Tactical operations (v9 ⭐ updated)

  • Vercel deploy via npx (no CLI install): npx vercel@latest --prod --yes
  • When CDP screenshots time out against motion-heavy pages, switch to curl -sI for status verification + the chrome JS tool for inspecting computed styles. Don't burn 20+ minutes fighting CDP retry loops. (v8 OP-08 + v9 reinforcement.)
  • Dev cache corruption is recurring. After production builds clobber the .next dir, rm -rf .next + restart preview. Symptom: Cannot find module './741.js'.
  • Never run npm install in pnpm projects. Lockfile mixing silently breaks builds.
  • Centralize repeated strings. v9 add: any "Mon-Sat" abbreviation pairs with hours via a BUSINESS.hoursShort constant — never let day-range appear without time.

  • TP-06 Directional card entrances (alternating left/right by grid position).

  • TP-08 Split layout for service areas (media one side, content other).
  • TP-09 Mobile execution non-negotiable. Verify on mobile.
  • TP-10 Featured + supporting review layout — hierarchy IS the design.
  • TP-11 Accent-colored category tags on cards (palette-locked).
  • TP-12 Process sections with visual connectors. v9: 2-col internal layout per card (icon + title + body LEFT, bullet stack RIGHT).
  • TP-13 Video hero by default.
  • TP-14 Proactive image generation. Don't make user ask.
  • TP-15 Brand-palette discipline. Programmatic + visual enforcement.
  • TP-16 Scale to section role. Supporting content starts smaller.
  • TP-17 Pattern propagation from user signals. Strong feedback → catalog pattern.
  • TP-18 Mid-build skill audit at every major iteration.
  • TP-19 Source-of-truth constants in lib/data.ts.
  • TP-20 Higgsfield realism via anti-prompts.
  • TP-21 ⭐ NEW v9 Match-the-word bar logic. When a bar/meter represents an attribute with a worded label (LOW/HIGH/etc.), bar fill matches literal magnitude of the word — NEVER a "score." LOW = small fill. HIGH = large fill. Viewers expect words and bars to agree without translation.
  • TP-22 ⭐ NEW v9 Clearly clickable at rest. Interactive elements must signal interactivity WITHOUT requiring hover. Stronger borders, ambient glows, persistent arrows, status pills. Hover is enhancement, not the only affordance.
  • TP-23 ⭐ NEW v9 Hours always pair with day-range. Never let "Mon-Sat" appear in caps without "9 AM – 6 PM." Centralize as BUSINESS.hoursShort.
  • TP-24 ⭐ NEW v9 Right-side fill is a slot, not a stat-only zone. The space next to a section header can hold stat anchors OR a thematic CTA card OR an AT A GLANCE bullet list — pick by what the section's downstream conversion needs.
  • TP-25 ⭐ NEW v9 Trim to deliberate counts. 6 cards in a 3-col grid often overwhelm. Trim to 4 in a 2x2 — feels deliberate. Same for spec lines (3-4 max), brand chips (3-6), location stats (4).

11Operating principles

Mental models that govern HOW Claude works. Cannot be overridden.

  • OP-01 Vision for taste, assertions for correctness. Use both.
  • OP-02 Never build UI blind. Look at the result after every meaningful change.
  • OP-03 Recognize inference vs perception. Always close the loop with perception.
  • OP-04 Scale to section role.
  • OP-05 Trust user taste signals broadly. Single-element feedback rarely about a single element.
  • OP-06 Brand-palette discipline — programmatic + visual enforcement.
  • OP-07 Audit tool/skill utilization mid-build.
  • OP-08 When verification stalls, switch tier. Don't burn time fighting CDP — pivot to deploy-and-verify.
  • OP-09 Save handoff docs to docs/. Files outlive any single conversation.
  • OP-10 Push back when a request risks the goal. Present 2-3 options with recommendation.
  • OP-11 ⭐ NEW v9 Operating-mode mantra discipline. When the user gives a task that references another section ("apply the home-page DNA here"), the implicit pattern is always: study the referenced section, identify its visual language, apply it without asking section-by-section direction. Confirm the plan tightly, then ship.
  • OP-12 ⭐ NEW v9 Standby mode for batched edits. When the user announces a "round of edits," queue them all without executing. Note each clearly with the planned approach. Wait for explicit "go" before any code changes. Reduces context-switching cost and lets the user think out a sequence end-to-end.
  • OP-13 ⭐ NEW v9 Cascading components are the leverage point. Edits to shared components (FaqSection, SignsGrid, MaterialsGrid, LocationPage) automatically propagate across every page that uses them. ALWAYS prefer component-level edits over page-level repetition. One change in FaqSection.tsx hits home + windows + doors + 6 location pages = 9 pages cleaned in one commit.

15Composition + creative freedom

v9 is a doctrine, not a template. Both worked examples ship the same recipes in different aesthetic modes. Future builds compose; they don't clone.

Posture Compose, don't clone. If a future build looks like a recolored AM, the doctrine has been misapplied. The recipes are modular. The aesthetic mode is chosen for the project. Creative judgment fills the gaps.

How to compose for a new project

  1. Pick an aesthetic mode from §03 (or extend with a new validated one). Lock palette per §04.
  2. Identify the project's structural shape — single page? multi-page? per-location? portfolio? audit tool?
  3. Pull recipes by need, not by template:
    • Need to prove a problem? Recipe 30 (Audit Ledger).
    • Need to compare options on the same axes? Recipe 38 (Spec-Sheet w/ tier bars).
    • Need a conversion fill instead of more stats? Recipe 41 (Thematic CTA card).
    • Need to present per-location intel? AM LocationPage composition (Recipes 38-43 stack).
    • Need scroll-driven counter dramatics? Recipe 31 (Dual Scrub Counter).
  4. Apply pattern library §05 for the standard signature elements (eyebrow + H2, stat anchor cluster, spec bullets, etc.).
  5. Run the verification contract §09 before declaring done.
  6. Save handoff doc in project's docs/ (OP-09).

When to deviate

  • The aesthetic mode requires it (Brutalist mode breaks several of the soft TPs by design).
  • The reference site direction overrides taste (TP < Reference per §02).
  • The user explicitly requests it (TP < User per §02).
  • Engineering rules and operating principles still hold. Always.
