The Self-Contained Principle

This doctrine is the entire reference. There is no v9 baseline + v10/v11/v12 supplements. Reading any single file (this one) gets the full picture. When a new session reaches a meaningful milestone, the next iteration produces a fresh self-contained document (v14, v15, ...) that supersedes v13 — never a supplement on top of v13. Supplements are banned. The doctrine is monolithic by design.

What "AI slop" means in this doctrine

AI slop is any frontend output where the visual language traces directly to training-data defaults rather than to the doctrine's design language. Telltales:

  • Sections built as plain bordered white cards with a centered eyebrow + h2 + paragraph + bullet list, with no asymmetric grid, no stat-anchor cluster, no glow underline, no motion choreography.
  • Section headers using plain <h2> instead of HeadingWithUnderline with the glow + typeIn treatment.
  • "3-column grid of bordered cards" as the universal answer to "I have a list of things to show."
  • Content composed from primitives (div + border + padding + Tailwind) instead of composed from the project's atom palette.
  • Bullet lists with no diamond markers, no pulse, no left rule.
  • Two-column "this vs. that" panels rendered as identical flat cards instead of as a paired light + dark contrast (or rendered without any layered background rhythm).

If any of those telltales describe what you're about to ship, the contract has been violated. The fix is not "polish later." The fix is don't write it that way the first time. Redesign upstream.

The Generation Reflex

Replace the default reflex of "I need a section; let me write a div with some Tailwind" with this reflex:

  1. What's the section's role? (Diagnose? Compare? Showcase? List? Convert?)
  2. Which existing atom serves that role? (§14 lists AM's flagship palette; §06 + §07 generalize.)
  3. If no atom fits, which DNA principles must the new atom carry? (§03.)
  4. Only after answering 1–3 do you write JSX.
Posture Compose using DNA, never compose from primitives. The doctrine is descriptive about what good looks like (recipes, anti-patterns, pattern library). The contract above is what makes the description active at generation time.

They are the always-true substrate the universal aesthetic (§04.1) is built on; the §04.2 variance library is how the principles get expressed differently per project. 3.1 · Cinematic motion language — the universal substrate

The motion language is the always-true substrate. Four constants apply to every contractor-site build, every brand mode, every motion intensity setting. They don't vary. If a recipe diverges from a constant, the recipe is wrong, not the constant.

  1. Universal entry ease curve: ENTER_EASE = [0.16, 1, 0.3, 1] (cubic-bezier expo-out). Declared once per project (or per-component if no shared file). Used on every entry transition site-wide. No "linear" for entries. No "ease-in-out" for entries (ease-in-out is reserved for the infinite-loop ambient pulses below). AM uses this curve 32× across 30 files. Both AM and KMv2 share it.
  2. Positive 200px pre-trigger viewport margin: viewport: { once: true, margin: "200px" } is the default on FadeUp / Stagger / SlideIn. Positive margin EXPANDS the IntersectionObserver root box so the reveal fires 200px BEFORE the element enters the viewport. This is the single biggest contributor to the "fluid" feel of AM and KMv2. Without it, reveals catch up to scroll position and feel stuttery. Negative margins ("-180px", "-160px") are used selectively for inner-bullet stagger delay only, never as section-reveal default. AM has explicit comments warning against the prior "-260px" default that broke this.
  3. Reduced-motion is non-negotiable: every motion primitive checks useReducedMotion() first and either renders a plain element (no motion wrapper) or sets initial={false} / duration: 0. The @media (prefers-reduced-motion: reduce) global CSS rule is required in globals.css as a final safety net (forces all animation/transition durations to 0.01ms). Both AM and KMv2 ship this rule.
  4. Ambient cadence pair — 2.4s for diamonds, 1.8s for alert dots: every infinite-loop pulse uses one of these two durations. Use 2.4s for spec/thread/ glance bullet markers (◆ pulsing markers, opacity [0.65, 1, 0.65], scale [1, 1.18, 1]) and section-bridge separators. Use 1.8s for navy-bg CTA pip dots + sticky CTA reinforcement (opacity [0.6, 1, 0.6], scale [1, 1.3, 1]). Other durations (9s hero vignette, 18s hero video zoom, 45-55s marquee) are specific to those atoms — see §04.6.5. Loops use ease: "easeInOut", not the ENTER_EASE expo-out.

Above-the-fold heroes run a 3-4 second cinematic cascade: eyebrow rises first (delay 0.2s), then H1 via TypeIn cinematic (delay 1.0s, per-char stagger 0.022s, so an 8-word H1 lands by ~2.2s), then subhead rises (delay 2.6s), then dual CTAs pop sequenced (delay 3.2s and 3.4s). Below-fold sections run the cascade ladder in §04.6.4 — eyebrow → H2 → subhead → cards → per-card inner cascade. Sub-1.5-second total section reveal feels stiff. 3-4 seconds feels intentional.

The §04.6 catalog implements these constants as 9 named primitives. The §03 DNA section names the principles; §04.6 names the atoms; §14.3 names the AM-specific implementations. All three reinforce the same vocabulary.

Caps-mono small text in the accent color, paired with a 40px horizontal rule on the left (or red diamond marker, or red dot). Sits above every section H2 and inside cards. Universal "this is what the next thing is" signal. Replaces uppercase plain text labels.

3.4 · Glow underlines on H2s

Section H2s use HeadingWithUnderline with fullWidth glow cinematic typeIn. A 3px accent-colored bar with a 2px glow shadow renders below the heading, scaling left-to-right as the typeIn completes. Plain underlines (no glow) read flat; the glow is what makes it feel cinematic.

3.5 · Stat-anchor clusters (the right-side fill default)

Big numeric value + caps-mono unit + muted label, anchored by a red vertical rule with offset dot. Exactly 3 anchors per section — never fewer. Numerals animate via StatCounter with target-scaled durations (small targets count faster — see anti-pattern 7.5). Pairs with the asymmetric header (§3.2) as the right column.

3-anchor minimum is a hard rule (NEW v13 session-8): if the section can't justify 3 distinct stats, do NOT ship a 1- or 2-anchor right column — the asymmetric grid leaves a visible empty rectangle. Instead, swap the right column to one of: Recipe 41 (thematic right-side CTA card), Recipe 42 (AT A GLANCE bullet card), or the reinforcement panel pattern from §06. Single-anchor right column = anti-pattern 7.28. Discovered session-8 plumbing-demo audit: FAQ section shipped with 1 stat anchor, right column read as broken/missing-content.

3.6 · Layered background rhythm

Sections alternate background surfaces: white → tint → navy/dark → white → tint → ... The visual rhythm comes from the transitions. A page where every section is the same background feels flat. A page where every section is a different jarring color feels chaotic. The right pattern is alternating white/tint/dark in deliberate sequence so the eye gets contrast at the right cadence.

3.7 · Photo-led composition where information is dense

When a section carries dense info, pair it with a real photo (hero), a stat callout overlaid on the photo (FloatingStat), or photo-led tiles (StyleGrid pattern). Image is anchor, not decoration. If no real photo exists, generate one via Higgsfield (§1.3) rather than ship flat content.

Photo aspect defaults (NEW v13 session-8):

  • Hero photo: 3:2 or 16:10 landscape. Portrait (4:5, 3:4) only when the subject is genuinely vertical — a tall installation (full-height window stack, two-story door, water heater rack), a person standing at attention. Default-landscape because contractor heroes pair with leftward H1 + CTA; portrait crops cut the H1 column off at common breakpoints and read as a LinkedIn profile, not a hero shot.
  • Tile photos (services / brands / before-after): 4:3 landscape. Matches the rhythm of grid layouts. Square (1:1) acceptable for square-grid contexts only.
  • Row photos (service areas, location tiles): 16:10 wide landscape. Reads as a strip across the bottom of city/area tiles.
  • Floating stat overlay on hero: stat card protrudes ~24px left of the photo edge with a 3px left accent rule. Verify the stat card doesn't clip viewport edge at narrow widths — set left: max(-24px, calc(-1 * var(--gutter))) or absolute positioning that respects the section gutter.

Discovered session-8 plumbing-demo audit: hero photo shipped at 4:5 portrait, read as profile shot rather than installer-on-doorstep. 3:2 landscape is correct default.

3.8 · Hover bloom and pulsing markers

Cards lift on hover (-translate-y-1), gain red shadow (shadow-[0_28px_56px_-24px_rgba(176,37,73,0.35)]), and reveal a bottom 2px accent rule that scales left-to-right. Red diamond bullet markers (◆) pulse subtly via animated opacity + scale. Pulsing dots in eyebrows. Everything has subtle life.

3.9 · The anti-flat-card discipline

⚠ Slop signatures — recognize and refuse (4 forms catalogued v13 session-2)

Form 1 — Flat editorial card: plain bordered white card + centered eyebrow + h2 + paragraph + bullet list. The training-data default reflex for "I need a content block."

Form 2 — Narrative section without a visual partner (NEW v13 session-2): cinematic header (good) → 3 paragraphs of body text stacked vertically (slop). Atom used HeadingWithUnderline + StatCounter — and still shipped slop because the body has no visual partner. Fix: photo+copy split (HomeWindowsTeaser shape — see §06.15 BrandNarrativeSplit) or structural-data partner (stat panel, tier bars, audit ledger). Prose without a visual partner reads as a blog article, not a doctrine-grade section.

Form 3 — Quick Answer at hero size (NEW v13 session-2): FaqSection answerBlock rendered as a giant white card with H3 + 4-line paragraph above the FAQ accordion. Should be a compact band — see §06.16 — at ~30% the visual footprint. AI Overview extraction works on compact form. Hero-sized answer block ≠ extraction lift.

Form 4 — Card grid with no per-card differentiation (NEW v13 session-2): 2x2 or 3x3 grid where every card is title + body + index marker, identical bordered rectangles with text alone inside. Fix: per-card single-word eyebrow (§06.9), per-card icon/glyph (SignsGrid), per-card tier bar (MaterialsGrid), or per-card pick-instead tag (BrandCaveats). Something that VARIES between cards — beyond the index number.

The flat editorial card is the training-data default. The doctrine exists to override it. Every time you catch yourself writing <div className="bg-white border rounded-md p-6"> <h2>...</h2> <p>...</p> <ul>...</ul> </div> that's the slop reflex. Replace with: which atom? what DNA? And then render-check before you write (§00 Lock 4) — atom use alone doesn't immunize. The atom's data shape can permit slop. If it does, the atom is itself slop-prone — refactor the shape so long-form prose can't be passed in, or deprecate.

3.10 · "Compose using DNA, never compose from primitives"

On a project with existing atoms (AM — see §14), use them. On a project without atoms yet, invent the atoms first, then compose. Never write inline JSX that ignores the atom layer. If composing from primitives feels easier than picking or proposing an atom, that's the warning signal — stop and audit which atom this content maps to.

For the contractor-trade scope (plumbers, HVAC, electricians, roofers, painters, kitchen remodelers, general contractors, landscapers, hardscape), v13 ships ONE universal aesthetic — fleshed-out, no dead space, fluid, well-animated, not overstimulating. 4.1 · The universal King Maker aesthetic (always-true)

Five qualities that apply to every contractor-trade site, never selected against:

  • Fleshed-out — every section pulls its weight. No placeholder text, no half-built recipes shipped as final. If a section role isn't filled with real content, the section doesn't ship.
  • No dead space — visual rhythm fills the screen. Asymmetric headers, stat-anchor clusters, photo-led tiles, layered backgrounds. Empty white areas read as "missing content."
  • Fluid — sections flow into each other intentionally. The page reads top-to-bottom as a single experience, not a stack of independent boxes.
  • Well-animated — motion vocabulary applied consistently. Heading reveals on every H2 (per §04.2 pick). FadeUp + Stagger. Hover bloom. Pulsing markers. Subtle continuous life across the page.
  • Not overstimulating — motion is balanced. Continuous loops stop on prefers-reduced-motion. Animated separators don't crowd content. Counter durations scale to target size (anti-pattern 7.5).

The §03 DNA principles ARE the universal aesthetic in detail. The §06 patterns + §07 recipes are how the DNA is implemented. The §04.2 variance library is how each new project draws from the implementation pool with deliberate novelty.

4.9.2 — Preconditions (what makes the loop work)

  1. Doctrine must be specific enough to fail. §04.7's "ProcessSteps MUST ship alternating-direction card entry + icon spring-pop tile + 2-col internal layout + per-bullet motion.li cascade + scroll-triggered inset halo + right-drawn title underline + card-level whileHover boxShadow bloom + rail with copper glow" is checkable. "Make it feel cinematic" is not.
  2. Fixes must be bounded. The loop's hard constraint of ≤3 file touches per auto-applied fix prevents snowballing into rewrites. Larger fixes get queued with "too-big" note for user scope decision.
  3. Hybrid doctrine application. V13_DOCTRINE_ADDITIVE changes (new §04.7 rows, new §04.6 atoms, new anti-patterns — purely growing the doctrine) auto-apply inline so subsequent iterations build on them. V13_DOCTRINE_SUBTRACTIVE changes (modifying existing rows, removing constants, restructuring) queue for end-of-run human review because they have blast radius beyond the current project.
  4. HIGH/MED/LOW severity rubric. The rubric gates what auto-applies vs what queues. Without it, the loop would either auto-apply everything (risky) or apply nothing (slow). HIGH = §04.7 MUST row missing entirely, or §04.8 utilization audit returns zero for a primitive. MED = nested MUST attribute missing (e.g. underline ships but lacks "with accent glow" sub-spec). LOW = polish (copy refinement, spacing tweak, color saturation).
  5. Iteration counter + state file on disk. The loop persists progress to {project}/.audit-loop-log.md + {project}/.audit-loop-punchlist.md so wake-ups across iterations don't re-do work, and so the loop is auditable after the fact.

4.9.3 — Loop mechanics (per iteration)

  1. Read state file. Determine iteration N. If N = 1, run pre-flight per §01.1 + load tools.
  2. Run §04.8 utilization grep audit. Output Primitive utilization: ... line.
  3. Read each section file in components/sections/. For each, identify §04.7 MUST-row items missing. Compare against the section's row.
  4. Spot-check 1 section per iteration via Chrome MCP against AM + KMv2 live (rotate: iter 1 Hero, iter 2 ProcessSteps, iter 3 Testimonials, iter 4 CTABand, iter 5 Footer). If Chrome MCP unavailable, source-only audit is sufficient because §04.7 is precisely worded enough to grep.
  5. Compile gap list. Each gap gets: severity (HIGH/MED/LOW) + category (HOLLOWAY_IMPL / V13_DOCTRINE_ADDITIVE / V13_DOCTRINE_SUBTRACTIVE).
  6. Auto-apply: HIGH HOLLOWAY_IMPL + all V13_DOCTRINE_ADDITIVE. Queue: MED+LOW HOLLOWAY_IMPL + all V13_DOCTRINE_SUBTRACTIVE.
  7. Verify in preview (DOM stats: transformed elements, blurred-char initial states, nested anchors, section count). Append iteration block to log file.
  8. If N < 5 (or scope-equivalent): call ScheduleWakeup for iteration N+1. If N = max: do NOT schedule; surface end-of-run review.

4.9.4 — End-of-run review

The final iteration does NOT schedule a wakeup. Instead it surfaces:

  • Summary table — all iterations side-by-side (applied vs queued counts).
  • Final DOM verification + delta vs iteration 1.
  • Final §04.8 utilization line — verify all 9 primitives still ≥ threshold.
  • HOLLOWAY_IMPL punchlist — MED/LOW items waiting for user approve/veto per item.
  • V13_DOCTRINE_SUBTRACTIVE queue — restructuring proposals waiting for considered review.
  • Preview link for visual scroll-through.

    • 4.9.5 — Hard constraints (NEVER violate)

    • NEVER skip pre-flight on iteration 1.
    • NEVER schedule wakeup if currentIteration === N (where N is the scope's max).
    • NEVER auto-apply V13_DOCTRINE_SUBTRACTIVE.
    • NEVER add new motion primitives beyond the 9 in §01.7 — flag as doctrine question, queue for review.
    • NEVER apply a fix that touches >3 files — downgrade to QUEUED with "too-big" note.
    • NEVER modify {project}/.audit-loop-log.md retroactively (append-only).
    • NEVER restart from iteration 1 if log already shows N entries — resume from N+1.
    • NEVER claim "shipped" without §10 VC-12 + Lock 6 + Lock 7 evidence statements.

    4.9.6 — Failure modes (graceful handling)

    • If a fix throws a syntax error → revert, log "applied with errors — reverted", continue.
    • If preview server won't start → log it, continue with source-only audits.
    • If Chrome MCP unavailable → use source reads only, log the limitation. Doctrine is precisely worded enough that source-only audits produce concrete fixes.
    • If git status shows uncommitted changes from prior work → leave them alone, work on top.
    • If .audit-loop-* files are corrupted → back them up with .bak suffix, start fresh from iteration 1.
    The bigger insight (v13 session-13 codification) The audit loop separates doctrine authoring from doctrine application. Doctrine authoring is creative, contested, requires human judgment every turn — do it in chat. Doctrine application is mechanical compliance checking — do it in a loop. This workflow split scales: chat for creative work, loop for enforcement work. Every contractor project after v13 session-13 follows this split by default.

08Anti-pattern catalog (7.1–7.33)

Failure modes that cost real time during real builds. Avoid in future builds.

7.1 · Red-on-navy caps eyebrow

Dark-on-dark — ~2.5:1 contrast. Illegible. Fix: text-white/85 font-semibold with red dot accent as the only red.

7.2 · FadeUp / Stagger negative viewport margin claiming "pre-trigger"

Negative margin SHRINKS the trigger box — elements have to scroll DEEPER in before firing. Backwards. Use positive 200px for actual pre-trigger.

7.3 · JSX from 'use client' module across RSC boundary

JSX exports from 'use client' modules don't survive RSC import. Put JSX (icons, etc.) in non-client modules so server components can pass them as props.

7.4 · Bar fill = "score" instead of literal magnitude

LOW maintenance with HIGH bar reads as contradiction. Fix: bar literally matches the word — LOW = short bar, HIGH = long bar.

7.5 · StatCounter with fixed duration on small targets

1.1s to count 0→6 holds visibly at 0. Scale duration: ≤10 → 0.45s, ≤50 → 0.6s, ≤100 → 0.8s, larger → 1.0s.

7.6 · v8 carry-forward

  • Wide outer glow halos creating strikethrough — cap at 2px alpha 0.55
  • mb-* inside HeadingWithUnderline className — routes to outer wrapper, creates overline effect
  • filter: blur(*) on text animations — removed sitewide; opacity + offset only
  • "Playing card" 4-up color-coded stat blocks — rejected; use structured cards with rhythm
  • Off-palette accents — gold/yellow/teal in AM, red in KMv2 — palette discipline
  • Deploying without clearing dev cache — rm -rf .next between heavy edit batches
  • playbackRate < 1.0 on hero video — halves frame rate, visible stutter
  • Hooks-in-loop in React 19 strict — kills parent silently; extract loop body to child

7.7 · Ambiguous symptom icon (▲)

Plain unicode triangle reads as up-arrow/expand/sort. Use proper SVG warning-triangle-with-! glyph for universal "this is a problem" semantic.

7.8 · Filled-pill accent on caps-mono spec card

Filled-red pill in caps-mono context reads as bolted-on foreign element. Match smallest existing unit — red dot + caps eyebrow.

7.9 · Layered header weight

Utility strip + hairline + 2 red CTAs + active dot + active underline = 6 red appearances in header. Strip back to ≤3. One accent line, one filled CTA color, one active-state cue.

7.10 · Auto-stretched grid columns with top-anchored content

Two-col grid stretches both cells, but lighter column's content stays top-anchored → visible empty gap. Fix: Recipe 45 (flex + justify-between on lighter column at lg+).

7.11 · Statement-form copy on self-identification cards

"Drafts at the threshold." reads as flat statement. "Drafts at the threshold?" triggers reader to self-check. One ? per title.

7.12 · Multiple filled-red CTAs without hierarchy

Two filled-red CTAs in same header compete. Distinguish via icon, label, or size — or make one outlined.

7.13 · Right-cluster long-text overflow at md/lg

Header action CTAs showing full text labels at md+ (768+) overflow viewport. Push long text to xl+ (1280+), use short label at sm–lg.

7.14 · Trailing viewBox whitespace

SVGs with viewBox extending past content waste pixels at every render size. Audit + crop via Recipe 49.

7.15 · Badge-only mobile brand fallback

Swapping full lockup → badge alone below sm. First-time mobile visitors can't read company name. Always show wordmark (Recipe 49 + 50 to make room).

7.16 · Hyperlocal pages without real photos

Location × product pages without real install photos collapse into "templated reasoning + local color sprinkled on top" — the doorway pattern Google's spam policy names. Evidence: May 2024 HCS de-indexed ~500/700 geo-templated pages from one site.

7.17 · Trusting fabricated specific content claims

"22% lower energy bill," "4.9/5 from 30+ reviewers" — unverified specifics create legal + reputation risk. Verify with customer OR use safer vaguer framings.

7.18 · Word-count uniqueness without topic-level uniqueness

80–90% word-level uniqueness still fails doorway-page detection if reasoning is templated. The swap test: swap city/product on a page; if it still reads correctly, it's a doorway. Topic-level uniqueness beats word-level.

7.19 · Self-serving review schema on LocalBusiness

Google hasn't rendered star rich results from Review markup on own LocalBusiness since 2019. AggregateRating only OK with third-party reviews. Audit + strip self-collected on-site Review/AggregateRating.

7.20 · Deprecated HowTo schema

Deprecated Sept 2023, removed from Search Console. Strip if present.

7.23 · Atom membership is not slop immunity (NEW v13 session-2)

"Atom from §14.2 ≠ slop-free output." An atom + slop content = slop output. BrandWhyNarrative was in the v13 session-1 palette, used per spec, used HeadingWithUnderline + StatCounter — and still shipped 3-paragraph wall-of-text slop because the atom's data shape allowed long-form prose (paragraphs: readonly string[]). The §00 Render Preview Lock (Lock 4) is the structural prevention at write-time. Atoms whose data shape permits slop are themselves slop-prone — refactor the shape (force lede + threads[4], not paragraphs[]) or deprecate. v13 session-2 deprecated BrandWhyNarrative and added BrandNarrativeSplit with a type-locked shape that prevents prose stacking at write-time.

7.24 · items-end on an asymmetric header grid when the LEFT column is taller (NEW v13 session-2)

Inverse of 7.10. Two-column asymmetric grid (e.g. lg:grid-cols-[1.3fr_1fr]) with items-end bottom-aligns both columns. If the LEFT column (eyebrow + cinematic H2 + subhead) is taller than the RIGHT column (single panel card or stat cluster), items-end pushes the RIGHT column DOWN to align bottoms — creating 200-240px of empty space ABOVE the right-column content. The right-side stat anchor cluster (§06.2) floats disconnected from the heading, with no visual relationship between the two columns.

Diagnostic: measure eyebrow Y vs. right-column-top Y. If right column starts 100px+ below the eyebrow with no visual reason, this anti-pattern is firing.

Fix: change items-end → items-start on the header grid. Top-aligns both columns so the eyebrow and the first stat anchor sit at the same Y. Discovered v13 session-2 on BrandLinesGrid, BrandWhenRight, BrandCaveats — all three atoms had inherited the items-end pattern from a v12 era where the right column was always SHORTER than the left and the bottom-align made visual sense. When the right column became stat clusters or reinforcement panels of varying height, the alignment broke. Default to items-start for asymmetric header grids unless there is a specific reason to bottom-align.

7.25 · Claiming "shipped" off the git push alone (NEW v13 session-3)

git push origin main is a CODE PUSH, not a deploy. Production ships only when the platform's deploy mechanism fires. On Vercel projects with GitHub auto-deploy disabled (audit: Deployments tab → "source" column always vercel deploy, never a commit hash), the push lands on GitHub but production stays on the prior build until npx vercel deploy --prod --yes runs from the linked web/ directory. Same trap exists on any platform where the CI hook isn't wired — the symptom is identical and the verification is identical.

Symptom in the wild: 36 brand-image assets + 6 product-line atoms pushed to origin/main, declared shipped. User reported "duplicate photos" across Chrome, Chrome incognito, and Edge — three independent cache surfaces, same failure. 13SEO doctrine for 2026

What Google actually rewards in 2026. Grounded in 3 parallel-agent audit findings from Google Search Central docs, BrightLocal 2026 ranking factors, Sterling Sky 8186-business study, Search Central blog, web.dev.

13.1 · What Google actually rewards (ranked by leverage)

  1. Google Business Profile completeness + correct primary category. #1 local-pack factor per BrightLocal 2026. Customer-gated.
  2. Steady review velocity with text reviews. Review weight rose 16% → 20% of local-pack 2023–2025. Monthly volume > total count. Customer-gated.
  3. First-hand experience content with named authorship. Helpful Content guidance explicitly rewards "first-hand expertise + depth of knowledge." Person schema for owner, real install photos.
  4. Schema graph: LocalBusiness + Service + Product + FAQPage + BreadcrumbList. Foundational. Use HomeAndConstructionBusiness as more-specific type. Add areaServed with Wikipedia sameAs, hasCredential for licenses, employee/founder Person nodes.
  5. Core Web Vitals at p75 in CrUX field data. LCP < 2.5s, INP < 200ms (replaced FID March 2024), CLS < 0.1.
  6. Internal linking with descriptive varied anchor text. Mueller: "one of the biggest things you can do" for SEO. Zyppy's 23M-link study: variety + 2-5 word descriptive anchors beat repetitive.
  7. Earned citations from authoritative local sources. BBB, chamber, supplier dealer-locator pages, local press. Mueller de-emphasizes raw link count, prioritizes earned/relevant.
  8. HTTPS + mobile-friendly. Table stakes. Absence is a flag; presence doesn't move the needle.

13.2 · What Google penalizes

  • Doorway pages — explicitly named in Google's spam policy: "multiple domain names or pages targeted at specific regions or cities that funnel users to one page."
  • Scaled content abuse (May 2024 spam policy) — "many pages for the primary purpose of manipulating Search rankings," AI- or human-written. Applies even if "well-written."
  • Helpful Content System — folded into core ranking March 2024, site-wide. Thin pages drag the whole domain's classifier down.
  • Link-buying / footer links across unrelated sites. Manual-action risk.
  • Faking freshness via updated dates + thin filler. HCS hammers this pattern.

13.3 · The swap test (operational rule)

Definition: if you can take a page and swap the city or product modifier, and the page still reads correctly without other rewrites, it's a doorway page.

Every hyperlocal or category-variant page must pass the swap test. Topic-level uniqueness beats word-level uniqueness. Subdivision names, local routes, climate notes — all are "local color" if the page's reasoning is identical to peers.

13.4 · The 18-page safe ceiling for hyperlocal expansion

Multi-town single-location contractor: safe ceiling for hyperlocal expansion is ~18 pages (6 enhanced town landings + up to 12 town × category overviews). Above 40 pages is documented penalty territory. Penalty risk scales with pattern strength, not just count.

13.5 · AI Overview citation patterns

  • Only ~1.2% of local businesses get cited by AI per SOCi's 350K-location analysis.
  • AI citation drivers: NAP consistency across 10+ platforms, review velocity (3x lift), FAQ schema with prompt-shaped Q&A (2.8x lift), third-party mentions, GBP optimization.
  • NOT driven by hyperlocal page count.
  • AI crawlers (GPTBot, ClaudeBot, PerplexityBot, Google-Extended) don't execute JavaScript. SSR/SSG initial HTML is required. Next.js 15 default behavior is sufficient.
  • Robots.txt: explicitly allow all AI crawlers — being cited in AI Overviews is the new local pack.

13.6 · The 70/30 customer-gated rule

For a local contractor: ~70-90% of SEO leverage is customer-gated (GBP, reviews, photos, authorizations). The other 10-30% is engineer/agency unilateral (schema, internal linking, meta tags, technical hygiene). Don't pretend engineering-only SEO captures the bulk of upside.

13.7 · Matrix in link graph, never in URL tree

To get N × M coverage across products × locations without doorway URLs: use the ProductLocationsStrip pattern (§6.15, Recipe 51-extended). 14 products × 6 cities = 84 paired anchors in the link graph, zero matrix URLs. Anchor text patterned "{Product} in {City}, NC" carries both contexts.

15Composition + creative freedom

The doctrine constrains output quality. It does not dictate specific components. Project-specific atoms diverge; the DNA stays the same.

Posture Compose using DNA, invent atoms per project. If a new build looks like a recolored AM, the doctrine has been misapplied. If a new build looks fundamentally different from AM but every section embodies the §03 DNA, the doctrine has been correctly applied.

How to compose for a new project

  1. Pick an aesthetic mode from §04 (or extend with a new validated one). Lock palette per §05.
  2. Identify the project's structural shape — single page? multi-page? per-location? portfolio? audit tool?
  3. For each section, map to AM atom equivalent (§14.4), pull DNA principles, invent project-specific atom that carries them.
  4. Apply pattern library §06 for the standard signature elements (eyebrow + H2, stat anchor cluster, spec bullets).
  5. Run the verification contract §10 before declaring done.
  6. Save handoff doc in project's docs/ (OP-09). At project milestone, write a fresh self-contained doctrine document (v14 of THAT project's doctrine, not a supplement).

When to deviate

  • The aesthetic mode requires it (Brutalist mode breaks several soft TPs by design).
  • The reference site direction overrides taste (TP < Reference per §02).
  • The user explicitly requests it (TP < User per §02).
  • Engineering rules + operating principles + Generation Contract always hold.

16The self-contained doctrine principle

v13 banishes the supplement chain. This is the structural fix for the v9-v10-v11-v12 problem.

Why supplements were wrong

  • Loading discipline failure. Supplements rely on "read v9 first, then v10, then v11, then v12." If a session loads only the latest, ~90% of the doctrine is missing.
  • Inheritance is load-bearing but invisible. Each supplement's "Inherited from..." section is the seam that fails silently when predecessors aren't loaded.
  • The supplement chain compounds. v12 inheriting from v11 inheriting from v10 inheriting from v9. Five files to read. Reality: only the latest gets read.

The v13+ model

  • Every major milestone produces a fresh self-contained doctrine document. v13 contains everything. v14 (when it lands) will contain everything v13 contained + new material + corrections — not as deltas, as a rewrite.
  • Previous versions become historical artifacts, preserved on disk but not part of the load chain.
  • No "inherited from" sections in v13+. If a recipe applies, it's listed here. If a TP applies, it's listed here. If an OP applies, it's listed here.
  • OP-14 deprecated. "Doctrine evolves additively" was the rule that built the supplement chain. v13 replaces with: doctrine evolves via monolithic rewrite at milestone boundaries.

When v14 happens

Triggers for v14 doctrine rewrite:

  • AM launches into production (DNS cutover + GBP optimized + form creds wired + 90 days of real GSC data) — confirms or revises the SEO doctrine §13.
  • A second flagship-quality build ships, contributing recipes that supplant or extend AM's atom palette.
  • The doctrine accumulates enough learnings that supplementing this v13 would be cleaner than rewriting — at which point, rewrite anyway.

v14 doctrine will be a full rewrite. Same structure (§00 Contract → §17 Build State). Old recipes drop if deprecated, new recipes are added, the AM build state freezes its v13-era snapshot to history and replaces with current state. The supplement chain stays banished.
