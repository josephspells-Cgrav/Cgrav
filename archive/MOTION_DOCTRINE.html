01King Maker DNA — universal design language

Ten principles. Constant across every contractor-trade project. The motion catalog in §03 is the implementation; the DNA names the principles. §01.8 ("Pulsing dots in eyebrows. Everything has subtle life") is the most-bypassed clause in v13's history. Surfaced first so it cannot be missed.

Most-missed clause · surfaced first

3.8 · Hover bloom and pulsing markers. Cards lift on hover (-translate-y-1), gain red shadow (shadow-[0_28px_56px_-24px_rgba(176,37,73,0.35)]), and reveal a bottom 2px accent rule that scales left-to-right. Red diamond bullet markers (◆) pulse subtly via animated opacity + scale. Pulsing dots in eyebrows. Everything has subtle life. No decorative glyph, eyebrow dot, or rail marker is allowed to be static. Every visible ◆ ◯ ● gets the 2.4s pulse (diamonds) or 1.8s pulse (alert dots). See §03.5 ambient loop catalog for exact specs.

1.1 · Cinematic motion language — the universal substrate

The motion language is the always-true substrate. Four constants apply to every contractor-site build, every brand mode, every motion intensity setting. They don't vary. If a recipe diverges from a constant, the recipe is wrong, not the constant.

  1. Universal entry ease curve: ENTER_EASE = [0.16, 1, 0.3, 1] (cubic-bezier expo-out). Declared once per project (or per-component if no shared file). Used on every entry transition site-wide. No "linear" for entries. No "ease-in-out" for entries (ease-in-out is reserved for the infinite-loop ambient pulses below). AM uses this curve 32× across 30 files; KMv2 shares it. ENTER_EASE is re-declared at the top of every primitive file + 27 section files. No shared motion/easing.ts — each file copies the constant.
  2. Positive 200px pre-trigger viewport margin: viewport: { once: true, margin: "200px" } is the default on FadeUp / Stagger / SlideIn. Positive margin EXPANDS the IntersectionObserver root box so the reveal fires 200px BEFORE the element enters the viewport. This is the single biggest contributor to the "fluid" feel of AM and KMv2. Without it, reveals catch up to scroll position and feel stuttery. Negative margins ("-180px", "-160px") are used selectively for inner-bullet stagger delay only, never as section-reveal default.
  3. Reduced-motion is non-negotiable: every motion primitive checks useReducedMotion() first and either renders a plain element (no motion wrapper) or sets initial={false} / duration: 0. The @media (prefers-reduced-motion: reduce) global CSS rule is required in globals.css as a final safety net (forces all animation/transition durations to 0.01ms).
  4. Ambient cadence pair — 2.4s for diamonds, 1.8s for alert dots: every infinite-loop pulse uses one of these two durations. Use 2.4s for spec/thread/ glance bullet markers (◆ pulsing markers, opacity [0.65, 1, 0.65], scale [1, 1.18, 1]) and section-bridge separators. Use 1.8s for navy-bg CTA pip dots + sticky CTA reinforcement (opacity [0.6, 1, 0.6], scale [1, 1.3, 1]). Other durations (9s hero vignette, 18s hero video zoom, 45-55s marquee) are specific to those atoms — see §03.5. Loops use ease: "easeInOut", not the ENTER_EASE expo-out.

Above-the-fold heroes run a 3-4 second cinematic cascade: eyebrow rises first (delay 0.2s), then H1 via TypeIn cinematic (delay 1.0s, per-char stagger 0.022s, so an 8-word H1 lands by ~2.2s), then subhead rises (delay 2.6s), then dual CTAs pop sequenced (delay 3.2s and 3.4s). Below-fold sections run the cascade ladder in §03.4 — eyebrow → H2 → subhead → cards → per-card inner cascade. Sub-1.5-second total section reveal feels stiff. 3-4 seconds feels intentional.

1.2 · Asymmetric 1.4fr/1fr header grid

Almost every section's header is a two-column row: heading + eyebrow + subhead LEFT, stat-anchor cluster OR thematic CTA card OR AT A GLANCE bullet list RIGHT. The ratio is roughly 1.4fr/1fr — heading column is wider, anchor column is denser. Centered headers are the exception, not the rule.

1.3 · Hierarchical eyebrows with red rule + ◆ markers

Caps-mono small text in the accent color, paired with a 40px horizontal rule on the left (or red diamond marker, or red dot). Sits above every section H2 and inside cards. Universal "this is what the next thing is" signal. Replaces uppercase plain text labels.

Glyph size minimum: decorative eyebrow glyphs (◆ ◯ ▸ lightning / droplet / leaf SVGs) must render at ≥13×17px to be perceivable at eye-level scroll distance. Smaller reads as visual noise. When the eyebrow is an inline-flex container, glyph children require flex-shrink: 0 + explicit min-width — flex defaults squash them to ~5px at narrow container widths, breaking the signal entirely.

1.4 · Glow underlines on H2s

Section H2s use HeadingWithUnderline with fullWidth glow cinematic typeIn. A 3px accent-colored bar with a 2px glow shadow renders below the heading, scaling left-to-right as the typeIn completes. Plain underlines (no glow) read flat; the glow is what makes it feel cinematic. Glow spec: boxShadow "0 0 2px rgba(accent, 0.55)" — exactly 2px, alpha 0.55, never wider (anti-pattern: wide outer glow halos creating strikethrough).

1.5 · Stat-anchor clusters (the right-side fill default)

Big numeric value + caps-mono unit + muted label, anchored by a red vertical rule with offset dot. Exactly 3 anchors per section — never fewer. Numerals animate via StatCounter with target-scaled durations (small targets count faster — see §02 PP-13 below). Pairs with the asymmetric header (§1.2) as the right column.

3-anchor minimum is a hard rule: if the section can't justify 3 distinct stats, swap right column to Recipe 41 (thematic CTA card), Recipe 42 (AT A GLANCE bullet card), or reinforcement panel pattern. Single-anchor right column = anti-pattern 7.28 (see REFERENCE_LIBRARY).

1.6 · Layered background rhythm

Sections alternate background surfaces: white → tint → navy/dark → white → tint → ... The visual rhythm comes from the transitions. A page where every section is the same background feels flat. A page where every section is a different jarring color feels chaotic. Alternating white/tint/dark in deliberate sequence gives the eye contrast at the right cadence.

1.7 · Photo-led composition where information is dense

When a section carries dense info, pair it with a real photo (hero), a stat callout overlaid on the photo (FloatingStat), or photo-led tiles (StyleGrid pattern). Image is anchor, not decoration. Generate via Higgsfield rather than ship flat content.

Photo aspect defaults: hero 3:2 or 16:10 landscape (NOT portrait — portrait crops cut the H1 column off and read as a LinkedIn profile); tile photos 4:3 landscape; row photos 16:10; floating stat overlays protrude ~24px left of photo edge with 3px left accent rule (verify with left: max(-24px, calc(-1 * var(--gutter))) at narrow widths).

1.8 · Hover bloom and pulsing markers — EVERYTHING HAS SUBTLE LIFE

Generation rule — applies to every visible glyph + marker

Cards lift on hover (-translate-y-1), gain red shadow (shadow-[0_28px_56px_-24px_rgba(176,37,73,0.35)]), and reveal a bottom 2px accent rule that scales left-to-right. Red diamond bullet markers (◆) pulse subtly via animated opacity + scale.

Pulsing dots in eyebrows. Everything has subtle life. Every visible ◆ inside an eyebrow, every dot on a stat anchor, every rail dot on a ProcessSteps timeline, every chip dot, every CTA pip — has the appropriate ambient loop attached (2.4s for diamonds, 1.8s for alert dots; see §03.5). Static decorative glyphs are slop.

1.9 · The anti-flat-card discipline

⚠ Slop signatures — recognize and refuse (4 forms)

Form 1 — Flat editorial card: plain bordered white card + centered eyebrow + h2 + paragraph + bullet list. Training-data default reflex.

Form 2 — Narrative section without a visual partner: cinematic header (good) → 3 paragraphs of body text stacked vertically (slop). Atom used HeadingWithUnderline + StatCounter and still shipped slop because the body has no visual partner. Fix: photo+copy split (BrandNarrativeSplit shape) or structural-data partner (stat panel, tier bars, audit ledger).

Form 3 — Quick Answer at hero size: FaqSection answerBlock rendered as giant white card with H3 + 4-line paragraph above the FAQ accordion. Should be compact band at ~30% the visual footprint. AI Overview extraction works on compact form.

Form 4 — Card grid with no per-card differentiation: 2x2 or 3x3 grid where every card is title + body + index marker. Fix: per-card single-word eyebrow, per-card icon/glyph, per-card tier bar, or per-card pick-instead tag — something that VARIES between cards beyond the index number.

1.10 · "Compose using DNA, never compose from primitives"

On a project with existing atoms (AM — see REFERENCE_LIBRARY §14), use them. On a project without atoms yet, invent the atoms first, then compose. Never write inline JSX that ignores the atom layer. If composing from primitives feels easier than picking or proposing an atom, that's the warning signal — stop and audit which atom this content maps to.

02Motion-relevant engineering bans (Priority 5)

Carry Priority 5 with the Generation Contract — never overridden by taste, reference site, or user instruction. The bans below specifically prevent broken motion + perf failures.

IDBanReason
PP-08No infinite boxShadow animationsReal paint cost. Use opacity or filter.
PP-09No width/height/top/left animationsLayout reflow per frame. Use transform + opacity only.
PP-10No setInterval countersDrifts and re-renders. Use useMotionValue or rAF.
PP-11No HTML video playbackRate < 1.0Halves frame rate → stutter. Generate at native long duration (Cinema Studio 3.0 12s, not 6s + playbackRate 0.5).
PP-12No negative IntersectionObserver margin claiming "pre-trigger"Negative margin POST-triggers. Use positive 200px for true pre-trigger.
PP-13No StatCounter with fixed duration on small targets1.1s to count 0→6 holds visibly at 0. Scale duration: ≤1 → 0.35s, ≤10 → 0.45s, ≤50 → 0.6s, ≤100 → 0.8s, >100 → 1.0s.

Hydration + framework — non-negotiable

  • 'use client' on every component using Framer Motion or GSAP. No exceptions.
  • useGSAP() hook for all GSAP in React. Never raw useEffect + gsap.context.
  • GSAP and Framer Motion never target the same DOM element. One element, one animation system.
  • Hooks-in-loop is fatal in React 19 strict. Never call FM hooks (useTransform, useMotionValueEvent, useScroll) inside .map(). Extract loop body to child component.
  • JSX exports from 'use client' modules don't survive RSC boundaries. Put JSX (icons) in non-client modules so server components can pass them as props.
