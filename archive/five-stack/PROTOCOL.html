5-Stack Motion Generation Protocol

Experimental workflow targeting ~95% doctrine compliance for fully-automated motion-heavy contractor sites. Overrides the static-first default. Stacks five interventions: two-doctrine read-checkpoint, section-by-section verification, AST normalization, agent split, manual final pass. Mechanical brute force where compression-based architecture failed.

EXPERIMENTAL · OVERRIDES STATIC-FIRST · LOADS ON EXPLICIT TRIGGER

00Overview — when to use this protocol

This protocol activates when the user explicitly says "5-stack experiment" or pastes the launch prompt from §09. It OVERRIDES the static-first default in ~/.claude/CLAUDE.md for the duration of the session — motion generation is ENABLED. The protocol exists to test whether stacked verification can achieve ~95% doctrine compliance on a motion-heavy contractor site.

The five stacks

  1. Two-doctrine read-checkpoint. Load STRUCTURE_DOCTRINE + MOTION_DOCTRINE (NOT split into three). Read each in chunks. Output a "key clauses captured" checklist after each chunk — anchors values in transcript.
  2. Section-by-section verification. Build one section, capture via Playwright, grep for required clauses, run axe, gate next section on pass.
  3. AST normalization. Run web/scripts/normalize-motion.mjs after each section. Deterministic post-generation rewriter adds missing ambient pulses, normalizes cascade timings, completes hover catalog. Catches what compression dropped.
  4. Agent split (Structure + Motion subagents). Structure Architect ships static atoms via Agent tool. Motion Choreographer wraps that output in cascade ladder + ambient loops + hover catalog. Each subagent has dedicated intent slot for one concern.
  5. Manual final pass. User reviews the agent's output and applies remaining touch-up. The 95% ceiling assumes ~20-30 min of manual cleanup per site.

Compliance target

Target: ~95% perceived site-level compliance. ~90% on combinatorial clauses (per-card cascade, ambient pulse coverage, hover catalog). ~98% on single-value clauses (cascade ladder timings, brand palette, hero spec).

Cost ~3-4x baseline token cost per project. Significant tedium per project. If results don't justify the cost after this experiment, fall back to static-first as the production architecture.

Why checkpoints work The checkpoint OUTPUT is what anchors values in transcript. The decay rate of transcript context is slower than the decay rate of context-only loading.

06AST normalization — what the script does (stack 3)

web/scripts/normalize-motion.mjs is a deterministic post-generation rewriter. It scans the generated JSX file, identifies known patterns where compression typically drops specs, and inserts the missing clauses. See the script source for current capabilities.

Transformations the script performs

TransformDetectInsert/normalize
Ambient pulse on bare ◆ Any <span> / <p> child containing literal "◆" without surrounding motion.span wrapper Wrap in motion.span with 2.4s opacity+scale loop + delay i*0.3
Ambient pulse on alert dots Any element with class containing "rounded-full" + "bg-{accent}" + size w-2 h-2 or w-3 h-3, not already in motion.X Convert to motion.span with 1.8s opacity+scale loop
Cascade timing normalization FadeUp/HeadingWithUnderline with delay values not matching §03 ladder (e.g. delay 0.05, 0.18 are wrong; should be 0.00, 0.50, 0.45) Replace with canonical ladder values based on element role inferred from context
Hover catalog completion Any element with className containing "group" but missing hover:-translate-y, hover:shadow-, or group-hover children Add card-lift basic (hover:-translate-y-1 transition-all duration-300) at minimum
ENTER_EASE declaration File uses framer-motion but doesn't declare ENTER_EASE constant at top Inject const ENTER_EASE = [0.16, 1, 0.3, 1] as const; after imports
Reduced-motion guard File uses motion.X without useReducedMotion check or motion-reduce: utility Inject useReducedMotion + conditional render or animation skip
transition-all duration default fix className with "transition-all" but no explicit duration-* utility Append duration-300 (cards) or duration-200 (nudges/icons) based on element role

Usage

# Dry run (show what would change without writing)
node web/scripts/normalize-motion.mjs --section hero --file path/to/Hero.tsx --dry-run

# Apply transformations
node web/scripts/normalize-motion.mjs --section hero --file path/to/Hero.tsx

# Full-page run (all sections in app dir)
node web/scripts/normalize-motion.mjs --all --dir web/app/[project]/

# Output to stdout (JSON) for tooling integration
node web/scripts/normalize-motion.mjs --section hero --file path/to/Hero.tsx --json
Scaffold state The initial scaffold at web/scripts/normalize-motion.mjs has the detection patterns documented as TODOs. Transformation logic is partially implemented. The script SHOULD work for "Add pulse to bare ◆" and "ENTER_EASE declaration" out of the box. Other transforms require iteration. Plan to implement transforms in order of impact: ambient pulses first (highest payoff), cascade timing normalization second, hover completion third.

07Final ship check + manual touch-up (stack 5)

After all sections shipped through the §05 loop, run the final ship check before claiming the run complete. Then user does manual touch-up pass.

Automated final checks

  1. Full-page Playwright capture at desktop (1440×900) and mobile (iPhone 13)
  2. axe-core full-site run — 0 critical, 0 serious
  3. VC-01 through VC-12 audit (per STRUCTURE §08)
  4. Compression-check final output: re-Read STRUCTURE_DOCTRINE §00-§04 + MOTION §01-§04, output "Locks satisfied: 1✓ 2✓ ... 11✓" with evidence
  5. Per-section compliance scoring (see §08)

Manual touch-up pass (stack 5)

User reviews captures and applies remaining corrections. Typical gaps to look for:

  • Static decorative glyphs that should pulse (AST normalize should catch most but not all)
  • Hover gestures missing on specific elements where the catalog should apply
  • Cascade timing drift on specific cards where AST normalize didn't infer the role correctly
  • Reduced-motion fallbacks missing on specific motion.X usages
  • Copy edits (motion doesn't fix word choice)
  • Per-card cd offsets that drifted from i*0.06-0.12 range

Expected touch-up time: ~20-30 minutes for a SMALL tier site, ~45-60 for MEDIUM, ~90+ for LARGE.

08Compliance scoring

At end of run, compute compliance score so we can evaluate whether the 5-stack actually hit the 95% target. Honest measurement — no rounding up.

Scoring formula

Per section:
  - Atom palette compliance: [pattern matched / total sections] × 1.0 weight
  - Cascade ladder compliance: [sections with correct delays / total] × 1.5 weight
  - Ambient loop coverage: [glyphs with pulse / total decorative glyphs] × 1.5 weight
  - Hover catalog coverage: [hover gestures present / applicable] × 1.0 weight
  - Per-card inner cascade: [cards with icon+title+bullets / total cards] × 1.0 weight
  - Reduced-motion: [primitives with guard / total] × 0.5 weight
  - axe: 0 critical/serious required, else fail × 2.0 weight
  - VC-01 through VC-12: [passed / 12] × 1.0 weight

Site total: weighted sum / max possible × 100%

Target tiers

  • 95-100% — Hit the target. 5-stack confirmed viable.
  • 85-94% — Improvement vs baseline (~30-40%) but didn't hit target. Identify where it failed; consider whether the gap is closeable.
  • < 85% — Below the 2-file + checkpoint ceiling. Something in the stack regressed. Diagnose.

Honest reporting
