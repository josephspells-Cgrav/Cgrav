08Anti-pattern catalog (7.1–7.33)

Failure modes that cost real time during real builds. Avoid in future builds.

7.1 · Red-on-navy caps eyebrow

Dark-on-dark — ~2.5:1 contrast. Illegible. Fix: text-white/85 font-semibold with red dot accent as the only red.

7.2 · FadeUp / Stagger negative viewport margin claiming "pre-trigger"

Negative margin SHRINKS the trigger box — elements have to scroll DEEPER in before firing. Backwards. Use positive 200px for actual pre-trigger.

7.3 · JSX from 'use client' module across RSC boundary

JSX exports from 'use client' modules don't survive RSC import. Put JSX (icons, etc.) in non-client modules so server components can pass them as props.

7.4 · Bar fill = "score" instead of literal magnitude

LOW maintenance with HIGH bar reads as contradiction. Fix: bar literally matches the word — LOW = short bar, HIGH = long bar.

7.5 · StatCounter with fixed duration on small targets

1.1s to count 0→6 holds visibly at 0. Scale duration: ≤10 → 0.45s, ≤50 → 0.6s, ≤100 → 0.8s, larger → 1.0s.

7.6 · v8 carry-forward

  • Wide outer glow halos creating strikethrough — cap at 2px alpha 0.55
  • mb-* inside HeadingWithUnderline className — routes to outer wrapper, creates overline effect
  • filter: blur(*) on text animations — removed sitewide; opacity + offset only
  • "Playing card" 4-up color-coded stat blocks — rejected; use structured cards with rhythm
  • Off-palette accents — gold/yellow/teal in AM, red in KMv2 — palette discipline
  • Deploying without clearing dev cache — rm -rf .next between heavy edit batches
  • playbackRate < 1.0 on hero video — halves frame rate, visible stutter
  • Hooks-in-loop in React 19 strict — kills parent silently; extract loop body to child

7.7 · Ambiguous symptom icon (▲)

Plain unicode triangle reads as up-arrow/expand/sort. Use proper SVG warning-triangle-with-! glyph for universal "this is a problem" semantic.

7.8 · Filled-pill accent on caps-mono spec card

Filled-red pill in caps-mono context reads as bolted-on foreign element. Match smallest existing unit — red dot + caps eyebrow.

7.9 · Layered header weight

Utility strip + hairline + 2 red CTAs + active dot + active underline = 6 red appearances in header. Strip back to ≤3. One accent line, one filled CTA color, one active-state cue.

7.10 · Auto-stretched grid columns with top-anchored content

Two-col grid stretches both cells, but lighter column's content stays top-anchored → visible empty gap. Fix: Recipe 45 (flex + justify-between on lighter column at lg+).

7.11 · Statement-form copy on self-identification cards

"Drafts at the threshold." reads as flat statement. "Drafts at the threshold?" triggers reader to self-check. One ? per title.

7.12 · Multiple filled-red CTAs without hierarchy

Two filled-red CTAs in same header compete. Distinguish via icon, label, or size — or make one outlined.

7.13 · Right-cluster long-text overflow at md/lg

Header action CTAs showing full text labels at md+ (768+) overflow viewport. Push long text to xl+ (1280+), use short label at sm–lg.

7.14 · Trailing viewBox whitespace

SVGs with viewBox extending past content waste pixels at every render size. Audit + crop via Recipe 49.

7.15 · Badge-only mobile brand fallback

Swapping full lockup → badge alone below sm. First-time mobile visitors can't read company name. Always show wordmark (Recipe 49 + 50 to make room).

7.16 · Hyperlocal pages without real photos

Location × product pages without real install photos collapse into "templated reasoning + local color sprinkled on top" — the doorway pattern Google's spam policy names. Evidence: May 2024 HCS de-indexed ~500/700 geo-templated pages from one site.

7.17 · Trusting fabricated specific content claims

"22% lower energy bill," "4.9/5 from 30+ reviewers" — unverified specifics create legal + reputation risk. Verify with customer OR use safer vaguer framings.

7.18 · Word-count uniqueness without topic-level uniqueness

80–90% word-level uniqueness still fails doorway-page detection if reasoning is templated. The swap test: swap city/product on a page; if it still reads correctly, it's a doorway. Topic-level uniqueness beats word-level.

7.19 · Self-serving review schema on LocalBusiness

Google hasn't rendered star rich results from Review markup on own LocalBusiness since 2019. AggregateRating only OK with third-party reviews. Audit + strip self-collected on-site Review/AggregateRating.

7.20 · Deprecated HowTo schema

Deprecated Sept 2023, removed from Search Console. Strip if present.

7.21 · Narrative section without a visual partner

3 paragraphs of body text stacked vertically with no photo, image, stat panel, tier bars, or other structural visual partner — the canonical slop signature even when the atom uses HeadingWithUnderline + StatCounter. Cinematic header dresses up the slop but the body IS the slop. Fix: photo+copy split (§06.15 BrandNarrativeSplit) or a structural-data partner. Reading time should DROP, not rise, vs the section above.

7.22 · FaqSection.answerBlock rendered hero-sized

A giant white card with eyebrow + cinematic H3 + 4-line paragraph above the FAQ accordion. The Quick Answer should be a compact band (left rail + caps Q tag + question + caps A arrow + ≤30-word answer) — see §06.16. AI Overview extraction works on compact form just as well. Visual footprint cap: ≤30% of accordion footprint.

7.23 · Atom membership is not slop immunity

"Atom from §14.2 ≠ slop-free output." An atom + slop content = slop output. BrandWhyNarrative was in v13 session-1 palette, used per spec, used HeadingWithUnderline + StatCounter — and still shipped 3-paragraph wall-of-text slop because the atom's data shape allowed long-form prose (paragraphs: readonly string[]). The §00 Render Preview Lock is the structural prevention at write-time. Atoms whose data shape permits slop are themselves slop-prone — refactor the shape or deprecate.

7.24 · items-end on an asymmetric header grid when the LEFT column is taller

Inverse of 7.10. Two-column asymmetric grid (e.g. lg:grid-cols-[1.3fr_1fr]) with items-end bottom-aligns both columns. If the LEFT column is taller than the RIGHT, items-end pushes the RIGHT column DOWN to align bottoms — creating 200-240px of empty space ABOVE the right-column content. The right-side stat anchor cluster floats disconnected from the heading.

Diagnostic: measure eyebrow Y vs. right-column-top Y. If right column starts 100px+ below the eyebrow with no visual reason, this anti-pattern is firing.

Fix: change items-end → items-start on the header grid. Default to items-start for asymmetric header grids unless there is a specific reason to bottom-align.

7.25 · Claiming "shipped" off the git push alone

git push origin main is a CODE PUSH, not a deploy. Production ships only when the platform's deploy mechanism fires. On Vercel projects with GitHub auto-deploy disabled (audit: Deployments tab → "source" column always vercel deploy, never a commit hash), the push lands on GitHub but production stays on the prior build until npx vercel deploy --prod --yes runs from the linked web/ directory.

Symptom in the wild: 36 brand-image assets + 6 product-line atoms pushed to origin/main, declared shipped. User reported "duplicate photos" across Chrome, Chrome incognito, and Edge — three independent cache surfaces, same failure. Traced to CDN serving 2-hour-old prerendered HTML referencing /images/window-detail.webp (old stock placeholder) 4× per brand page. The new /images/brands/{slug}/{line}.webp paths were 404 on the CDN — never deployed.

Prevention is two-layered, both already in the doctrine: STRUCTURE §07.3 deploy command + STRUCTURE §08 VC-11 fetch-grep verification. Escalated to Lock 6.

7.26 · Wholesale-clone default-bleed

Shipping a contractor-trade project as a wholesale clone of AM or KMv2 across every variance dimension instead of composing a deliberate variance. Symptom: the new project looks like AM-in-different-colors. Visitor on multiple contractor sites built from the doctrine can't tell them apart.

Diagnostic: count the variance picks that come from one reference project. If 8 or 9 of 9+ dimensions trace to AM (or KMv2), default-bleed is firing. Typical safe distribution: AM = 4–5 picks, KMv2 = 2–3 picks, vertical-specific or hybrid (C) = 1–2 picks.

7.27 · Stock people on a no-people image-policy pick

When the project's variance composition picked image policy (B) property-led, no people, slipping stock headshots, posed team shots, or smiling-person hero photography back in breaks the pick. Common slip: agent picks (B) for a premium kitchen-remodel project, then the hero image gets generated as "happy family in finished kitchen" — undoes the premium-restraint signal.

Diagnostic: any image of a person on a project where image-policy pick is (B). Stock or staged, generated or real. None pass.

7.28 · Single-anchor right column on asymmetric header grid

The asymmetric 1.4fr/1fr header grid expects a stat-anchor cluster, thematic CTA card, or AT A GLANCE bullet panel on the right. Shipping a single stat anchor — or two — in the right column leaves a visible empty rectangle, making the section read as broken. The grid IS asymmetric; when the right column is undersized, the asymmetry reads as missing content.

Diagnostic: count .stat children of .stat-cluster. If <3, this anti-pattern is firing.

Fix: three real anchors OR swap the right column to Recipe 41 / 42 / 38. Never ship a half-filled right column.

7.29 · Inter / generic-sans default font

Banned by design-taste-frontend skill. Inter (and Roboto / Arial / system-ui defaults) is the recognizable AI-slop typography reflex. Default to Geist, Outfit, Cabinet Grotesk, or Satoshi for display + body. JetBrains Mono / Geist Mono for code and mono-caps eyebrows.

7.30 · Pure #000 / #fff neutrals (untinted)

Banned by both impeccable and design-taste-frontend skills. Pure black and pure white are flat against any chromatic palette — they read as un-considered defaults rather than deliberate brand choices. Tint every neutral toward the brand hue (chroma 0.005–0.01 in OKLCH; or for hex, shift R/G/B by 4–12 units toward the dominant brand color).

7.31 · Em dashes in body copy

Banned by impeccable skill. Em dashes are an AI writing tic that signals machine- generated copy at scroll glance even when the actual text is good. Replace per-context: clause separator = period or semicolon; aside/elaboration = comma or parentheses; introducing a list = colon. Title/wordmark separator = colon or pipe, NOT em dash.

7.32 · Side-stripe borders > 1px on cards / callouts / alerts

Banned by impeccable skill (absolute ban). This is a doctrine bug, not just a demo bug. Multiple v13 atoms ship side-stripe borders by default:

  • §06.16 Compact Quick Answer Band has border-left: 3px solid var(--am-red) on the left rail.

13SEO doctrine for 2026 (full)

What Google actually rewards in 2026. Grounded in 3 parallel-agent audit findings from Google Search Central docs, BrightLocal 2026 ranking factors, Sterling Sky 8186-business study, Search Central blog, web.dev. Essentials (13.1 / 13.2 / 13.3 / 13.6) live in STRUCTURE_DOCTRINE §09; the long-form rest is below.

13.1 · What Google actually rewards (ranked by leverage)

  1. Google Business Profile completeness + correct primary category. #1 local-pack factor per BrightLocal 2026. Customer-gated.
  2. Steady review velocity with text reviews. Review weight rose 16% → 20% of local-pack 2023–2025. Monthly volume > total count. Customer-gated.
  3. First-hand experience content with named authorship. Helpful Content guidance explicitly rewards "first-hand expertise + depth of knowledge." Person schema for owner, real install photos.
  4. Schema graph: LocalBusiness + Service + Product + FAQPage + BreadcrumbList. Foundational. Use HomeAndConstructionBusiness as more-specific type. Add areaServed with Wikipedia sameAs, hasCredential for licenses, employee/founder Person nodes.
  5. Core Web Vitals at p75 in CrUX field data. LCP < 2.5s, INP < 200ms (replaced FID March 2024), CLS < 0.1.
  6. Internal linking with descriptive varied anchor text. Mueller: "one of the biggest things you can do" for SEO. Zyppy's 23M-link study: variety + 2-5 word descriptive anchors beat repetitive.
  7. Earned citations from authoritative local sources. BBB, chamber, supplier dealer-locator pages, local press. Mueller de-emphasizes raw link count, prioritizes earned/relevant.
  8. HTTPS + mobile-friendly. Table stakes. Absence is a flag; presence doesn't move the needle.

13.2 · What Google penalizes

  • Doorway pages — explicitly named in Google's spam policy.
  • Scaled content abuse (May 2024 spam policy) — "many pages for the primary purpose of manipulating Search rankings," AI- or human-written.
  • Helpful Content System — folded into core ranking March 2024, site-wide. Thin pages drag the whole domain's classifier down.
  • Link-buying / footer links across unrelated sites. Manual-action risk.
  • Faking freshness via updated dates + thin filler. HCS hammers this pattern.

13.3 · The swap test (operational rule)

If you can take a page and swap the city or product modifier, and the page still reads correctly without other rewrites, it's a doorway page. Every hyperlocal or category- variant page must pass the swap test. Topic-level uniqueness beats word-level uniqueness. Subdivision names, local routes, climate notes — all are "local color" if the page's reasoning is identical to peers.

13.4 · The 18-page safe ceiling for hyperlocal expansion

Multi-town single-location contractor: safe ceiling for hyperlocal expansion is ~18 pages (6 enhanced town landings + up to 12 town × category overviews). Above 40 pages is documented penalty territory. Penalty risk scales with pattern strength, not just count.

13.5 · AI Overview citation patterns

  • Only ~1.2% of local businesses get cited by AI per SOCi's 350K-location analysis.
  • AI citation drivers: NAP consistency across 10+ platforms, review velocity (3x lift), FAQ schema with prompt-shaped Q&A (2.8x lift), third-party mentions, GBP optimization.
  • NOT driven by hyperlocal page count.
  • AI crawlers (GPTBot, ClaudeBot, PerplexityBot, Google-Extended) don't execute JavaScript. SSR/SSG initial HTML is required. Next.js 15 default behavior is sufficient.
  • Robots.txt: explicitly allow all AI crawlers — being cited in AI Overviews is the new local pack.

13.6 · The 70/30 customer-gated rule

For a local contractor: ~70-90% of SEO leverage is customer-gated (GBP, reviews, photos, authorizations). The other 10-30% is engineer/agency unilateral (schema, internal linking, meta tags, technical hygiene). Don't pretend engineering-only SEO captures the bulk of upside.

13.7 · Matrix in link graph, never in URL tree

To get N × M coverage across products × locations without doorway URLs: use the ProductLocationsStrip pattern (§06.17, Recipe 51-extended). 14 products × 6 cities = 84 paired anchors in the link graph, zero matrix URLs. Anchor text patterned "{Product} in {City}, NC" carries both contexts.

16The self-contained doctrine principle

v13 banished the supplement chain. This is the structural fix for the v9-v10-v11-v12 problem.

Why supplements were wrong

  • Loading discipline failure. Supplements rely on "read v9 first, then v10, then v11, then v12." If a session loads only the latest, ~90% of the doctrine is missing.
  • Inheritance is load-bearing but invisible. Each supplement's "Inherited from..." section is the seam that fails silently when predecessors aren't loaded.
  • The supplement chain compounds. v12 inheriting from v11 inheriting from v10 inheriting from v9. Five files to read. Reality: only the latest gets read.

The v13+ model

  • Every major milestone produces a fresh self-contained doctrine document. v13 contained everything. v14 (when it lands) will contain everything v13 contained + new material + corrections — not as deltas, as a rewrite.
  • Previous versions become historical artifacts, preserved on disk but not part of the load chain.
  • No "inherited from" sections in v13+. If a recipe applies, it's listed here. If a TP applies, it's listed here. If an OP applies, it's listed here.
  • OP-14 deprecated. "Doctrine evolves additively" built the supplement chain. v13 replaces with: doctrine evolves via monolithic rewrite at milestone boundaries.

The 2026-05-18 split — supplement chain still banished

The split into MOTION_DOCTRINE + STRUCTURE_DOCTRINE + REFERENCE_LIBRARY is NOT a return to supplements. It is a generation-architecture split:

  • MOTION + STRUCTURE are loaded together at session start, both required to fire as generation programs. Neither inherits from the other; they cover non-overlapping concerns.
  • REFERENCE is browsed on demand. It does not contain any clause not present in MOTION or STRUCTURE. It is the long-form narrative + worked examples + rendered previews.
  • Future v14 will be a fresh self-contained doctrine in the same three-file architecture, full rewrites of each file. The split is the new permanent shape; supplements stay banished.

When v14 happens

Triggers for v14 doctrine rewrite:

  • AM launches into production (DNS cutover + GBP optimized + form creds wired + 90 days of real GSC data) — confirms or revises the SEO doctrine §13.
  • A second flagship-quality build ships, contributing recipes that supplant or extend AM's atom palette.
  • The doctrine accumulates enough learnings that supplementing v13 would be cleaner than rewriting — at which point, rewrite anyway.
