(c) *Error/resume*: none — no checkpoint, no `--resume`, abort semantics undefined (F9). (d) *Page-count edge cases*: pages without title blocks (cover/3D/spec) classify `other` and route to nothing — survivable via the completeness gate — but **rotated sheets** (ARCH-E pages with a 90° `/Rotate`) put the title block off the bottom-right crop → misclassification → silently unrouted; rotation handling is nowhere. S1 batching tail (122 = 12×10+2) is trivial but unpinned. (e) *Run permissions*: anyone holding the env file can write prod from a laptop — acceptable internally, but state it. (f) *First-run vs re-run writer*: F20.

  **2. Underspecification sweep.** Each is a builder guess: §3 — corner count, openings-per-wall, ridge LF, per-segment heights, gable policy, shell system (F6); plate double-count (F7); waste (F11); per-unit rounding scale (F14); line label formats ("Windows — 3060SH ×N"?), line `sort` values across assemblies, baseboard minus door openings, crown-flag storage, "unpriced vs $0" display (F25). D5 — guard comparison target (F3), `--force` affordance on a *button*, price preservation on re-apply. D7 — timeout, retries, caching, prices (F21). §4 — meta-serving GET shape (F23), chip/tooltip copy (builders can't invent copy; not in plan). §5 — everything in the MISSING-CONTRACTS list below.

  **3. THE ONE THING.** Add the text-layer probe to gate 0 and re-order the read strategy text-first (F5). One `pdfjs getTextContent()` call per page settles it. It simultaneously: fixes the illegibility wall F4 documents (dimension strings become exact, not 65-DPI guesses), collapses cost under the $15 cap (schedules/dims/tags/sheet-IDs cost zero image tokens; vision shrinks to symbol-count and geometry sheets), and directly serves D6's ±2% LF metric. The runner-up (F1) is more *certain* but is a one-line schema fix once named; the pixel-first assumption is the only defect that, if wrong — and the evidence says it is — invalidates the architecture, the budget, and the accuracy story at once. Building the whole pipeline on rasterization without spending one function call checking the text layer is the plan's single most expensive omission.

  **4. D3 classify→route→extract attacked.** *Over-count*: within-class duplication (F16) — enlarged and multi-level plans are all `floor_plan`; the 95→4 probe measured cross-sheet duplication and the design kills that, but nothing kills same-class additivity; tile-overlap dedupe has no pinned entity key (R2); garage doors live in both door schedule and plan tags — no rule names their owner. *Under-count*: tag-only revision types dropped by schedule-authority (F8); area schedule printed on the *cover* sheet has no route — `heatedSF` goes missing and every ceiling/insulation/drywall derivation degrades with it; sets with no roof plan (common — roof info on the framing plan) route roof reads to a sheet that doesn't exist. *Mis-route*: R3 is admitted but the completeness gate only names the *assembly*, not the cause — the report must print "window schedule: classified `other`, p.87" or the reviewer re-hunts the classification by hand. Dedupe verdict: the design solves the measured trap and leaves its three siblings open.

  **5. §3 formulas attacked.** *Nonsense-on-real-buildings*: #1 omits footings/grade beams (F10); #4 double-counts the exterior bottom plate against #2 (F7); #6's single `ridgeLF` doesn't exist on gable+lean-to barndo roofs and presumes stick framing on a possible engineered shell (F6); #12/#15 flat-ceiling assumption on a vaulted barndo (F12). *Under-counters*: #3/#5 aggregate-ceil (F13); #9 gable ends. *Dangerous-to-assume rather than flag*: shell construction system (decides whether #2–#9 mean anything), truss spacing on a "plans defer trusses to supplier" set (flagged — good — but the count is fiction until the supplier layout lands; say so on the line), 16" OC itself under post-frame. *Acceptable as flagged*: 4" slab, R-values, stud height as label.

D5 guard sufficiency.** No. Two independent defects: the race (F2 — stale-client PUT after apply completes silently restores the pre-apply set; the guard checked a precondition that the delete-then-insert then didn't hold) and the self-defeat (F3 — every autosave rewrites the `updatedAt` the guard compares, so the intended pricing flow trips it; re-apply then zeroes typed prices). The concrete interleaving is in F2. Minimal fixes: revision-token conditional update as the single atomic gate (F2), provenance-based guard + price-preserving merge on re-apply (F3), one writer for S6/apply/button (F20).

  **7. D6 honesty.** The counted/derived skeleton is honest about what it measures and the "no claim before the table" law is right. It hides four things: (a) *formula fitness* — waste, footings, vault, per-segment studs are all "formula correctness: PASS" while quantities run systematically low (F10–F13); (b) *allocation error inside tolerance* — total wall LF can be within ±2% while int/ext LF is swapped, corrupting the stud/plate split the harness never checks; (c) *systematic vs random error* — a missed wall segment is missing LF, not ±2% LF, and propagates into studs, plates, sheathing, drywall, insulation simultaneously while five derived assemblies still read PASS; (d) *flag blindness* — a fully-flagged run passes SC1 (F15). Fixes: per-param provenance in the report, an int/ext split check, at least one derived assembly (studs for one room) hand-counted end-to-end, flag share printed per assembly, counted and derived never blended into one %.

  **8. R8 tile geometry.** Sheet at 300 DPI = 14,400 × 10,800 px. Cap = 1,568 px max dimension. With 8% overlap (step ≈ 1,442 px): cols = ⌈(14,400−1,568)/1,442⌉+1 = 10, rows = ⌈(10,800−1,568)/1,442⌉+1 = 8 → **80 tiles/sheet at native 300 DPI** (no downscale; 1/8" text ≈ 37 px — dimension strings genuinely legible). At 200 DPI the sheet is 9,600 × 7,200 → 7 × 5 = **35 tiles/sheet native** (1/8" text ≈ 25 px — still readable). The plan's 2×2 gives ~65 effective DPI (illegible, by the plan's own verified fact); R8's "4×6 @ ~1500px" read as cover-the-sheet gives ~175 effective DPI (large dims marginal, fine strings risky). Conclusion: per-tile dimension reading is feasible only at native 200–300 DPI tiling — 35–80 tiles/sheet, which breaks the budget (Answer 11) — so the correct design is not a better grid but a different read strategy: **dimension strings, schedules, tags, and sheet IDs from the vector text layer; rasterized tiles only for graphic content** (F5), with per-page raster fallback for scanned pages.

Keep vision for: symbol counts (outlets, fixtures, switches), roof-face geometry and hips/valleys, wall segments where no dimension string exists, anything purely graphic. If a page is a raster scan: text yield ≈ 0 → per-page fallback to the F4 tile grid, labeled in the report, and budgeted — a mixed set (scanned manufacturer cuts appended to a vector set is common in 122 pages) must not silently inherit scan economics for all pages. What breaks without the probe: the whole accuracy story on measured entities and the whole cost story, simultaneously.

  **10. Schema delta attacked.** `meta` jsonb's shape is fine for per-line display; what it fails: (a) *survival* — the existing PUT strips it (F1), CSV import strips it (F23), so every write path except apply is a meta leak; (b) *provenance* — no `runId` in the key list (F18), so the F3 guard and any "which run said this" question are unanswerable; (c) *versioning* — `estimate_versions.snapshot` excludes meta by design; flag state at generate-time is lost — acceptable for MVP drafts, note it for later. `takeoff_runs` fails reproducibility without `sourceSha256`/`sourceFilename` (F18). Query needs (flag chips per line, runs panel per project) are covered by the shape; no jsonb index needed at this volume. The apply orphan question resolves to: apply itself can write meta correctly — it's the *next autosave* that destroys it, which is F1, and it breaks the flag-review loop exactly where the loop lives.

  **11. Cost + failure bounding.** Token math (≈ w×h/750 per image): a 1,568² tile ≈ 3,300 tokens. At native 300 DPI (80 tiles/sheet), a conservative 20–30 routed sheets = 1,600–2,400 tiles ≈ **5.3–8M image input tokens — over the entire $15 budget before a word of prompt text or output, and before retries**. Even 200-DPI native (35 tiles) barely fits with zero margin. The plan's own $3–8 estimate implies only 4–10 sheets get detail reads, but its routing table routes 20–35 — estimate and design disagree 3–5×. Latency: sequential-only at 5–15s/call = 2–7 hours vs D1's "5–15 min." The S1 filter is the only bound and it's doing 3–5× less filtering than the budget assumes. Abort partial-state: undefined run-row status, no checkpoint, orphaned GBs of tiles, possibly an empty draft project + contact residue, and no resume so the next attempt repays full price (F9). Text-first reading (F5) is what actually gets the run inside its own cap.

Cross-WO contracts two builders will implement incompatibly.** See MISSING-CONTRACTS below — the worst are `paramsJson` (T2 produces, T1's S5 consumes; unpinned names), the run-report schema (T2 writes, T4's harness reads, T3 renders; three consumers, zero definition), the `meta` key set with types (T1 writes, T2 produces, T3 renders), and apply-route ownership (F19). T4 consuming a `reportJson` shape that exists only in T2's head is a guaranteed merge collision; "may fold into T2" is the plan tacitly admitting it.
