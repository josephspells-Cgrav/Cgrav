The existing guard's assertions (status 410) pass identically under `fetch` defaults (`redirect: 'follow'`), so there is no forcing function for the builder to change the client. **Failure scenario:** guard follows `/spam/` → 308 → 410, observes final status 410 with no Location on the final response, asserts green.   **F2 · HIGH · §2.3 vs §7 (ordering contradiction) ·** §2.3 prose reads: spam checks on normalized path → *then* "if NOT spam and the raw pathname had a trailing slash → 308" → *then* "A3/B sections operate on the normalized path." Literal reading: `/roof-replacement/` → 308 → `/roof-replacement` → 301 → `/services/roof-replacement` (two hops). The §7 oracle row says `/roof-replacement/` → `301 → /services/roof-replacement`, which reads as one hop and implies A3 runs *before* the normalization 308. The parenthetical "their regexes mostly tolerate `\/?$` already" reveals the author hadn't decided whether A3/B see raw or normalized paths — irrelevant if normalization runs first, decisive if it doesn't. **Failure scenario:** builder picks either order; whichever the orchestrator's live re-run didn't expect gets reported as a failure or an unargued deviation → rework loop on the core behavior of the WO. (Both orders are defensible: 308-first preserves today's two-hop parity; A3-first is a one-hop improvement.) **Minimal fix:** state the exact decision order as a numbered chain in §2.3 and rewrite the oracle row as the full expected chain (`308 → /roof-replacement → 301 → /services/roof-replacement`, or the one-hop form if A3 is to run first).

  **F3 · MED · §2.3 (root self-redirect) ·** The pseudo-code guards the *normalization* (`pathname !== "/"`) but not the *redirect condition*: "if the raw pathname had a trailing slash → 308 to normalized." `"/"` ends with `"/"`, and normalized === raw === `/`, so a literal implementation emits a 308 to itself — an infinite redirect loop on the site's most important URL. I7 states the intent ("Root / never redirected") but the §2.3 mechanics don't achieve it. **Failure scenario:** builder transcribes the prose; `/` → 308 Location: / → loop. Caught by the §7 `/ | 200` row only if that probe is run redirect-disabled (see F1). **Minimal fix:** specify the redirect condition as `rawHadSlash && normalized !== pathname`.

  ## ANSWERS

  **1. Coverage holes in the oracle matrix.** Missing request classes, concretely: (a) *multi-slash tails* — `/spam//` still 308-first under the literal one-strip code, and no row catches it (F6); (b) *encoded slashes* — `%2F` tail forms are a decode-behavior coin flip, unprobed (F11); (c) *query strings* — spam-with-query and legit-slash-with-query both unprobed, and the latter is the WO's own §2.2 requirement (F10); (d) *HEAD* — unspecified (F16, low); (e) *exactly `/`* — present as a row, good, but the §2.3 mechanics as written self-redirect it, so the row is load-bearing and must be probed redirect-disabled (F3+F1); (f) *the matcher-excluded set's slash forms* — `/quote/` has a row (good), but `/robots.txt/`, `/sitemap.xml/`, `/api/*/` don't, and I6's claim that they're unaffected is false (F5); (g) *host dimension* — apex vs www is in success criterion 1 but nowhere in the matrix (F9); (h) the legacy-301-with-slash row exists but its expected chain is ambiguous against §2.3 (F2).

  **2. Underspecification sweep.** Every place the builder must guess: the order of the normalization 308 vs A3/B (F2); the redirect condition for `/` (F3); whether "multi-slash defensive" means `replace(/\/+$/,"")` or the printed `slice(0,-1)` (F6); Location header absolute vs relative, in both emission and assertion (F4); the guard's redirect mode (F1); where the guard gets the 137 URLs and which 20 if sampling (F8); `CITY_NAMES` consumption shape (F14); how `npm run doorway-check` invokes node — flags and version — given package.json is frozen (F7); whether ARTICLES/BLOG lib exports exist (bounded guessing with a stated fallback — acceptable, but still a guess the WO could have eliminated by reading the files it clearly had access to); HTTP methods covered (F16).

  **3. Is §2.3 correct for Next.js 16 middleware semantics?** The core assumption — `skipTrailingSlashRedirect: true` disables the pre-middleware trailing-slash 308 so middleware sees the raw slash path — is the documented purpose of the flag, and middleware runs before filesystem routing, so its 410/308 wins. Design: correct. Assumptions that could be wrong, with empirical checks: (a) *the prod 308 comes from Next, not Vercel's edge layer* — locally unprovable either way; the check is the orchestrator's post-deploy live matrix, and the WO should say "if prod still 308s on slash-spam after deploy, the flag isn't honored at the edge — escalate, don't iterate blindly"; (b) *middleware receives the raw slash form* — proven or disproven by the dual-form positive controls, *if* they probe redirect-disabled (F1); (c) *the flag disables only the trailing-slash redirect* — check I6's list plus its slash forms (F5); (d) *Location form of a middleware 308* — probe and pin it (F4). The WO's own guard is the right verification instrument for b–d; it is currently specified in a way that can verify nothing (F1).

  **4. Doorway-check native-import risks.** What breaks: non-erasable TS syntax anywhere in the chain (enum/namespace/parameter properties → hard crash); value imports with extensionless or `@/`-alias specifiers (Node ESM can't resolve what the bundler could); transitive runtime imports that pull Next/React/fs-touching modules; and — uniquely dangerous here — *shape* drift, because type-stripping performs no typechecking, so `GLOSSARY_TERMS.map(t=>t.slug)` on a renamed export fails at gate runtime, not at `typecheck`. What the WO should have said: the constraint list above, applied to *every* derived source (glossary.ts and any `lib/articles/*.ts` it probes, not just cities.ts); the rule "type-only imports are free, value imports are suspect, aliases and extensionless specifiers are STOP conditions"; and a pre-flight step confirming the `doorway-check` npm script's node invocation supports type-stripping, since package.json is frozen and Node 22.6–22.17 needs the explicit flag.

  **5. Can the new controls pass vacuously or false-positive?** Yes — vacuously, and it's the worst defect in the WO (F1): under redirect-following defaults, every new "first-response 410, no Location" assertion passes against the *unfixed* behavior. The 308 control can't false-*pass* (a followed 308 yields 200 ≠ 308, so it fails noisily), but it can false-*fail* on the absolute-vs-relative Location mismatch (F4). Sampling 20 of 137 is unsound as specified — not because sampling is wrong, but because it's unstratified and unjustified: all 137 against localhost cost seconds, and first-20 sampling can miss an entire broken URL class (F8). Additionally, the guard proves the criteria only for the `next start` Node runtime; the WO's claim that it "mechanically proves 1 and 2" silently excludes the Vercel edge, which is where criterion 1 actually has to hold (F9).

  **6. Parallel-lane merge hazards.** No textual conflicts — disjoint files — but a runtime dependency the WO never names: Lane M's gates import the exact two files the other lanes edit. Content-count changes are safe by construction (derivation is count-agnostic, and the existing gate demonstrably tolerates drift — it passes today at 14-vs-20, so A7's +31 won't redden the hardcoded version either). Shape changes are fatal and silent (F7c, F13): a renamed export or field in either lib file breaks Lane M's gate at runtime with no merge conflict to warn anyone. The hazards the WO fails to name: the export/field contract itself; the rebase-order rule ("if a lib lane lands first, rebase and re-run gates before merging M"); and the inverse trap (F12) where M lands first and its newly-derived larger lists turn the gate red on pre-existing content gaps no one is scoped to fix.

  **7. THE ONE THING.** Add the redirect-mode mandate to §2.5: *all guard probes disable redirect following and assert on the raw first response, and the existing client's default is audited and named in the report.* Reason: it is the single load-bearing sentence for the WO's entire proof structure. Every other defect has a backstop — the ordering contradiction surfaces at the oracle matrix (F2), the `/` loop surfaces at its matrix row (F3), the I6 regressions are cosmetic (F5). But with redirect-following probes, the guard — the artifact the success criteria explicitly designate as the mechanical proof of criteria 1 and 2 — certifies the unfixed behavior as fixed, locally *and* in the orchestrator's post-deploy re-run if the same script is reused. One sentence converts the WO's proof from decorative to real. Without it, this WO can complete green and change nothing.
